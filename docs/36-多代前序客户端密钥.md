# 多代前序客户端密钥（N2 之"多代前序"部分）

> 本增量把机密客户端的旧密钥从"仅保留一代前序"扩展为**多代前序**：连续轮换时，每一代旧密钥各自保留到它自己的原始截止时间；后续轮换不会延长或复活更早的代。状态为**编码增量**，仅由远程 CI 验证。

## 1. 语义

- 每次 `rotate` 把**当时的当前密钥哈希**追加为一条前序记录，随后写入新的当前密钥；旧记录不改写、不延长。
- 认证时（`PreviousClientSecretAuthenticationProvider`）遍历该客户端**所有 `valid_until > now`** 的前序哈希，任一匹配即通过；当前密钥仍由框架 provider 优先校验。
- 下一轮轮换只做两件事：删除**已过期**的前序行、追加当前密钥；不会更新仍有效的更早代，也不会把已删除的代"恢复"。
- 每一代有独立截止时间；最老的一代到点即失效，即使之后又发生多次轮换。
- 仍然只存哈希（delegating password encoder），不存明文；不跨客户端移动记录。

## 2. 表结构（V19）

```sql
ALTER TABLE oauth_client_secret_previous DROP CONSTRAINT oauth_client_secret_previous_pkey;
ALTER TABLE oauth_client_secret_previous ADD COLUMN id uuid;
UPDATE oauth_client_secret_previous SET id=gen_random_uuid() WHERE id IS NULL;
ALTER TABLE oauth_client_secret_previous ALTER COLUMN id SET NOT NULL;
ALTER TABLE oauth_client_secret_previous ALTER COLUMN id SET DEFAULT gen_random_uuid();
ALTER TABLE oauth_client_secret_previous ADD CONSTRAINT oauth_client_secret_previous_pkey PRIMARY KEY (id);
CREATE INDEX client_secret_previous_active ON oauth_client_secret_previous(client_id, valid_until);
```

- 旧行自动回填 `id`；`client_id` 不再是主键，同一客户端可以有多行。
- `valid_until` 仍是每代自己的截止时间；查询按 `client_id + valid_until` 过滤。
- 不修改 V14–V18。

## 3. 轮换与认证

- `ClientAdminService.rotate` 在注册行锁内：`DELETE ... WHERE client_id=? AND valid_until<=now`，再 `INSERT` 当前哈希与新截止时间；随后更新当前密钥。
- 幂等键仍作用于 `admin_client_action(action='ROTATE')`：同键重放 409，不重复追加前序行。
- 公开客户端（NATIVE/SPA）仍拒绝轮换；类型/认证方式不可变。
- 认证期围栏（docs/33）继续在注册行锁内先判停用，再校验当前/多代前序；停用优先。

## 4. 回滚限制

V19 是**单向扩展**：回退到"单行前序"需要先删除同一客户端的多余前序行（保留哪一代由运维决定），否则旧键约束无法恢复。回退不应被用来"复活"已过期代；过期行按 `valid_until` 判断，不因回滚重新生效。
