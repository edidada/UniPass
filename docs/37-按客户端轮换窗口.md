# 按客户端轮换窗口（N2 之"自定义窗口"部分）

> 本增量允许为单个机密客户端设置密钥轮换重叠窗口；未设置时继承全局 `unipass.clients.secret-rotation-window`（默认 24 小时，1 分钟–7 天）。状态为**编码增量**，仅由远程 CI 验证。

## 1. 语义

- `oauth_client_status.secret_rotation_window_seconds`：`NULL` 表示继承全局；非空为 60–604800 秒（1 分钟–7 天）。
- `rotate` 计算重叠截止时间时优先使用该客户端的值，否则使用全局配置；响应 `previousSecretValidUntil` 反映实际生效窗口。
- 设置/清除窗口不会改变当前密钥、前序代、启用状态或删除墓碑；已删除客户端拒绝设置（409）。
- 设置/清除需要 `ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP` + 近期密码/MFA + 原因 + `Idempotency-Key`，与其它生命周期写一致；审计动作 `CLIENT_ROTATION_WINDOW_SET`，detail 仅 `client_id` 与 `window_seconds`（`global` 表示清除），不写密钥。
- 同一幂等键同 reason 重放返回当前窗口（只读，不重复审计）；同键不同 reason 返回 409。

## 2. 迁移（V20）

```sql
ALTER TABLE oauth_client_status ADD COLUMN secret_rotation_window_seconds integer;
ALTER TABLE oauth_client_status ADD CONSTRAINT client_rotation_window_range
 CHECK (secret_rotation_window_seconds IS NULL OR
        secret_rotation_window_seconds BETWEEN 60 AND 604800);
```

现有行默认 `NULL`（继承全局），无需 backfill。回滚：删除列会丢失每客户端窗口并全部回到全局；不影响已签发的密钥或前序哈希。

## 3. 接口

- `GET /api/admin/console/clients/{clientId}/rotation-window` → `{ "seconds": number|null, "effectiveSeconds": number }`（应用管理员）。
- `POST /api/admin/console/clients/{clientId}/rotation-window`，`Idempotency-Key` 必填，body `{ "seconds": number|null, "reason": string }` → 同上 200；`seconds=null` 清除覆盖。
- 边界：`seconds` 非空时必须 60–604800；reason 1–500 且无 ISO 控制字符；未知/已删除 404；无权限 403。
- 门户在应用操作区提供"轮换窗口"只读/编辑面板：显示当前有效秒数，留空保存即恢复全局。

## 4. 测试

- `ClientAdminIT.perClientRotationWindowOverridesGlobalAndCanBeCleared`：设置 120 秒后 rotate 的截止时间 = now+120；清除后回退全局 1 小时；59/604801/未知/非管理员分别 400/404/403；`WINDOW` 动作只记两次成功设置。
- `ClientManagementHttpIT.perClientRotationWindowIsBoundedAndAppliedByRotation`：HTTP 设置 300 秒并验证 rotate 响应约 300 秒；清除后 `effectiveSeconds=86400`；59 秒 400；审计员 403。
- 门户 `clients.test.ts`：读取/保存窗口、UUID 幂等键、越界在客户端拦截。
- 未本地运行；以远程 Maven JDK 17 CI 为准。
