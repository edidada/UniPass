# 飞书登录与显式绑定

2026-10-21，T5 后端增量。支持固定单应用、单租户的浏览器 OAuth 登录与显式绑定，复用 IAM MFA、OIDC、epoch 和授权族控制，默认关闭。真实租户、应用可用范围、权限传播、内嵌浏览器尚未验收；通讯录同步、外部密码写入、飞书客户端全局退出仍未交付。

## 官方契约与技术选择

|---|---|---|
| 授权 | GET `https://accounts.feishu.cn/open-apis/authen/v1/authorize`；client_id、response_type=code、redirect_uri、state、S256 challenge | [授权码](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code.md) |
| 换码 | POST `https://accounts.feishu.cn/oauth/v3/token`；form 编码，authorization_code、client_id、client_secret、code、同一 redirect_uri、code_verifier | [v3 token](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3.md) |
| 查询身份 | GET `https://open.feishu.cn/open-apis/authen/v1/user_info`；Bearer user_access_token，要求成功 code、tenant_key、open_id | [用户信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get.md) |

v2 正文已标为历史版本并推荐 v3，v3 明确支持 PKCE；旧授权页仍有暂仅 v2 的备注。因此固定 v3 + S256，不自动退回旧版或去掉 PKCE，实际兼容性须由 POC-03 验证。基本用户信息无需额外权限；不申请 offline_access，不保存平台 access/refresh token，不读取或匹配邮箱、手机号、员工号。

| 选项 | 取舍与决定 |
|---|---|
| 官方 SDK / JDK HTTP | 仅换码与取身份，采用 JDK 17 HttpClient 和已有 Jackson，固定官方域名，不新增 SDK 依赖。IAM 的 OAuth/OIDC 仍交给 Spring Authorization Server。 |
| v2 / v3 | 采用官方推荐的 v3，接口失败拒绝登录，授权码不重试。 |
| 自动匹配 / 显式绑定 | 仅允许已认证的 IAM 本人确认绑定，不依据可由管理员导入的邮箱推断身份。 |
| 内存 / PG state | PG 摘要记录与唯一约束支持多节点一次性消费，事务外访问平台。 |
| 永久开关 / 有期能力 | 运行开关和 PG 能力同时满足才开启；核验最多七天。这是项目复核策略，不是飞书 token 有效期。 |

## 浏览器流程

1. GET `/api/public/csrf` 后带返回的 CSRF header，POST `/api/connector/feishu/login/start`。已登录用户使用 `binding/start`，避免静默切换账号。
2. 返回 `authorizationUrl`，浏览器跳转固定官方授权地址。服务生成 32 字节随机 state，有效五分钟；PG 保存 `sha256:` 摘要、session/IP 摘要和归属。客户端不能指定回调或平台接口。
3. PKCE verifier 由 app secret、应用、租户和 state 经带用途前缀的 HMAC-SHA256 派生，challenge 为 S256，数据库不保存 verifier。secret 轮换导致在途授权失效，应重新开始。
4. 固定 GET callback 仅接受单个 state、code 或 error，跨浏览器、重复参数、过期和重放拒绝。PG 行锁消费 state，平台 code 的应用级摘要另有唯一约束；先提交消费，再换码。取消也消费 state。
5. 换码要求 HTTP 200、JSON、code=0、Bearer 类型与有效期，再用 user token 查询身份并校验固定 tenant_key。只按 `(tenant_key,open_id)` 找绑定；未知身份拒绝，不自动创建 IAM 用户。
6. 最终 PG 事务重查能力、用户状态、gate、epoch 和绑定；读取当前角色，创建密码/MFA 时间为空的 FEISHU principal。轮换 Redis session ID、作废匿名 CSRF token、清除旧 MFA 上下文，响应只含成功状态。
7. 已有因素或管理角色继续走 IAM MFA 挑战，OIDC amr 据实包含 feishu/otp。实际 LDAP 再认证成功才增加 pwd，不延长最初登录寿命，也不改变 FEISHU 来源。

每浏览器五分钟最多五次 start，同一来源地址最多二十次。PG advisory lock 分别串行化浏览器和地址计数，超限 429；来源使用服务器的 remote address，不接受请求参数覆盖，代理可信转发仍需部署验证。

换码和 userinfo 各有三秒总期限（含响应体）、两秒连接上限、64 KiB 体积上限，不跟随重定向。token 有效期必须为正整数秒且不超过一天，userinfo 返回后再次检查未过期。重复 JSON 字段、尾随 JSON、非法类型、跨租户均拒绝。429 返回限流，5xx/超时返回不可用，不回传远端错误详情。结果不明也不重试原 code，用户重新发起授权。

callback query 包含一次性 code/state，代理、访问日志、APM 和浏览器错误上报必须去掉该路由的 query；T7 页面接入时及时替换浏览器历史地址，不能保存授权 URL。应用没有把这些值写入审计或数据库明文，但这不代表外围日志已验收。

## 显式绑定与持续授权

`binding/start` 要求五分钟内真实密码证明、现有因素的近期 MFA，并且没有强制改密或因素恢复限制。回调仍须同一用户、session、epoch，再查强认证。一个 IAM 用户只有一个绑定，一个外部身份只能归一个用户；并发争抢返回 409，不能覆盖他人。相同身份可显式更新 bound_epoch，改换身份先解除绑定。

改密、因素变更、禁用、全局退出等既有 epoch fence 使旧 bound_epoch 过期，飞书身份不能自动绕过。需重新用目录密码登录、完成所需 MFA，再显式确认同一绑定。`binding/remove` 同样要求近期密码/MFA，删除绑定并递增 epoch，撤销旧会话和授权。

浏览器请求、授权码/刷新/内省读取与保存、JWT 签发和资源验证均检查 FEISHU 当前绑定及能力有效期。JWT 新增签名的 `unipass_auth_method`；旧纯密码 JWT 兼容。运行开关关闭也拒绝 FEISHU principal/JWT。能力自然到期无需后台作业即可拒绝下一次访问；能力或配置更新另外通过 PG trigger 提升所有已绑定用户 epoch，复用 V8 撤销族和后端退出队列。重新核验不能复活旧绑定或旧 token。

这里的实时能力指 PG 中的核验记录，不是每次请求都到飞书查询权限。尚未实现平台权限/冻结事件回调或轮询；收到权限回收通知后，操作员应立即 disable。七天复核上限不能作为外部权限撤销五秒生效的证明；该闭环继续属于未交付范围。

这里控制 UniPass 及集成 live 检查的业务应用。V10 `FEISHU_APP_REAUTH`/推送的生产投递适配器仍未注册，任务保持 BLOCKED，不能报告飞书客户端全局退出或外部投递成功。

## V11 与离线管理

新增 connector、capability、binding、flow、code_use、audit 六张表。connector 固定一个 app/tenant，默认停用，数据库拒绝修改或删除其身份；多应用/租户需独立设计和迁移，不能改配置复用旧 open_id。

初始 LOGIN/CONTACT_READ 为 UNVERIFIED，SESSION_REVOKE/PASSWORD_WRITE 为 UNAVAILABLE，后两项没有伪造可用端点。CLI 仅能记录 LOGIN 人工核验，其余能力不能经此命令开启。数据库操作员属于受信任边界，直接改库权限不在 CLI 防篡改范围内。

先执行 Flyway 或现有 `ClientAdminCli migrate`。配置受保护的 `UNIPASS_DB_URL/USER/PASSWORD`、`UNIPASS_OPERATOR_REF`、`UNIPASS_EVIDENCE_REF`。引用指向真实租户报告，不填 secret、code 或 token。以下命令不调用平台；record 命令只记录操作员断言，不能自动完成 POC-03：

```powershell
$jar = 'iam-server/target/iam-server-0.1.0-SNAPSHOT-exec.jar'
$launcher = 'org.springframework.boot.loader.launch.PropertiesLauncher'
java '-Dloader.main=com.test.examples.unipass.server.FeishuAdminCli' -cp $jar $launcher configure
java '-Dloader.main=com.test.examples.unipass.server.FeishuAdminCli' -cp $jar $launcher report
# 真实验证并留存证据后人工记录，有效七天，同时开启 PG connector。
java '-Dloader.main=com.test.examples.unipass.server.FeishuAdminCli' -cp $jar $launcher record-login-verification
java '-Dloader.main=com.test.examples.unipass.server.FeishuAdminCli' -cp $jar $launcher disable
```

configure 从 `UNIPASS_FEISHU_APP_ID/TENANT_KEY` 读取固定身份，不接收 secret。写操作的操作员/证据引用同事务审计；report 输出能力、日期、链接、配置和绑定数量，不输出人员 open_id 或秘密。

IAM 运行另设 `UNIPASS_FEISHU_ENABLED=true`、同一 app/tenant、`UNIPASS_FEISHU_APP_SECRET`、`UNIPASS_FEISHU_CALLBACK=https://<IAM同源>/api/connector/feishu/callback`。回调必须 HTTPS、与 issuer authority 相同、精确路径，无 query/fragment/userinfo；在平台登记同一地址。只配置环境变量而没有有效能力记录，仍返回 503。secret 不放入 Git、URL 或命令参数。

每分钟清理一天前创建的 flow 和一天前的 code-use，每类每次最多一百行，不清理绑定或审计。平台 code 官方有效五分钟，摘要保留一天用于隔离重放。规模清理吞吐与审计归档仍须验收。

## 发布与回退

先关闭联邦入口、迁移 V11、升级全部消费安全上下文的 IAM 节点，再配置应用/租户、完成真实报告、记录能力，最后开运行开关。旧节点忽略来源与持续绑定检查，不能混跑。secret 轮换先 disable，更新全部节点秘密后重新验证、显式续绑。

回退先 disable，确认 epoch/授权族吊销，关闭新联邦入口，清理新来源会话并重新目录登录，再回退二进制；保留 V11 数据，不做破坏性 down migration。真实集群发布与跨站浏览器回跳尚未验收。
