## 1. 工程结构

`unipass-iam` 内部模块划分：

```
unipass-iam/
├── iam-authn          # 认证引擎（密码/OTP/扫码）
├── iam-token          # 令牌签发与吊销
├── iam-password       # 密码策略与修改
├── iam-session        # 会话管理（Redis）
├── iam-protocol       # OIDC/SAML/CAS 协议适配
├── iam-app            # 应用（客户端）注册管理
├── iam-audit          # 审计日志
└── iam-common         # 公共模型与工具
```

分层约定：`Controller（协议端点）→ Service（领域逻辑）→ Repository（PG）/ LdapGateway（目录）/ CacheGateway（Redis）`。目录访问只允许经由 `LdapGateway` 单一出口，便于统一超时、连接池与降级策略。

## 2. 认证接口详细设计（OIDC 授权码模式）

### 2.1 授权端点 `GET /oauth/authorize`

| 参数 | 必填 | 说明 |
|------|------|------|
| response_type | 是 | 固定 `code` |
| client_id | 是 | 应用注册时分配 |
| redirect_uri | 是 | 必须与注册值完全匹配 |
| scope | 是 | `openid profile email` |
| state | 是 | CSRF 防护随机串 |
| code_challenge | 移动端必填 | PKCE S256 |
| code_challenge_method | 移动端必填 | 固定 `S256`，不接受 `plain` |
| nonce | 建议 | 写入 id_token 用于重放防护 |
| prompt | 否 | `none`（静默）/`login`（强制重认证）/`consent` |

处理逻辑：

1. 校验 `client_id` 存在且 `status=ACTIVE`；否则返回 `invalid_client`（不重定向）。
2. 校验 `redirect_uri` 与注册白名单**逐字符匹配**（scheme/host/port/path/query 均精确匹配，禁止前缀匹配）；不匹配返回 400，禁止重定向，防止开放重定向。
3. 已存在有效 SSO 会话且 `prompt != login` → 生成 code 直接 302 回跳。
4. 无会话 → 渲染/跳转统一登录页，`state` 与 `redirect_uri` 存入服务端临时上下文（Redis key `unipass:authz:{ctx}`，TTL 10 分钟），不回传至前端拼接。
5. code 生成：`SecureRandom` 32 字节 Base64URL；Redis 记录 `unipass:code:{code}` → `{userId, clientId, redirectUri, challenge, nonce, sid}`，TTL 60 s，读取即删除（原子 `GETDEL`）。

### 2.2 令牌端点 `POST /oauth/token`

请求体（`application/x-www-form-urlencoded`）：

```
grant_type=authorization_code
&code={auth_code}
&redirect_uri={same_as_authorize}
&client_id={client_id}
&code_verifier={pkce_verifier}
```

客户端鉴权支持 `client_secret_post` / `client_secret_basic` / `private_key_jwt`（机密客户端使用服务端密钥；原生 App 为公共客户端，仅用 PKCE 不持有密钥）。

响应：

```json
{
  "access_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "def...",
  "id_token": "eyJ..."
}
```

校验顺序（任一失败即返回对应 OAuth error）：客户端鉴权 → `redirect_uri` 一致性 → code 存在且未被消费 → PKCE 验证（`BASE64URL(SHA256(code_verifier)) == code_challenge`）→ 用户状态仍然有效 → 签发。

**refresh_token 轮换**：`grant_type=refresh_token` 每次返回新的 refresh_token 并使旧值失效；若检测到已失效的旧 refresh_token 被再次使用，判定为泄露，立即吊销该会话组并写 `TOKEN_REUSE_DETECTED` 审计。

**access_token（JWT）claim**：

```json
{
  "iss": "https://pass.corp.example.com",
  "sub": "u-10086",
  "aud": "crm-web",
  "exp": 1793500000,
  "iat": 1793496400,
  "sid": "S-9f2c...",
  "employee_no": "E10086",
  "auth_epoch": 7,
  "amr": ["pwd"],
  "scope": "openid profile email"
}
```

`/oauth/userinfo` 返回 `sub, name, employee_number, email, phone, department, avatar, locale`，字段按 `scope` 与应用的字段授权配置过滤。

### 2.3 门户内部认证接口 `POST /api/authn`

```json
{ "username": "E10086", "password": "...", "mfa_code": "123456", "client_id": "app-mobile", "device_id": "..." }
```

认证成功仅设置门户会话 Cookie，继续原授权上下文，不向 App 直接签发 token，不向脚本暴露 sid；需 CSRF 防护。App 使用系统浏览器授权码 + PKCE。限流见 §7.4。

### 2.4 登出与吊销

| 接口 | 方法 | 说明 |
|------|------|------|
| `/oauth/logout` | GET / POST | 框架 RP-Initiated Logout，校验 ID-token hint 与登记退出地址；有 IAM 认证时全局 fence，无认证时仅撤销 hint 对应授权族 |
| `/oauth/revoke` | POST | 标准 RFC 7009，`token` + `token_type_hint`，吊销 access/refresh |
| RP origin 的 `/logout/backchannel` | POST | 接收 form logout_token，验签、上下文及 jti 防重放后按 sid 清本地会话；不是 IAM origin 的公共业务接口 |

仅删除 IAM 侧会话不等于应用登出。V8 在撤销事务中持久入队，由后台向已登记 `backchannel_logout_uri` 发送含 sid/sub 的 JWT；不另设匿名触发通知的 IAM HTTP 接口。实现、升级重登、重试与未完成验收见 [后端退出通知](21-OIDC后端退出通知.md)。A1/A5 仍需完整接入和外部环境证据。

## 3. 密码服务详细设计

### 3.1 修改密码 `POST /api/password/change`

```json
{ "old_password": "...", "new_password": "...", "confirm_password": "..." }
```

处理采用可恢复的跨系统状态机，而非 LDAP/PG 原子事务：

1. 会话与近期认证校验，验证旧密码、新密码及目录原生历史策略。
2. 以 Idempotency-Key 创建操作记录，同一用户串行；PG 提交 PREPARED、BLOCKED gate 和递增 auth_epoch，阻断旧凭证签发与使用。
3. 写目录：AD 用户改密 delete(old)+add(new)，管理员重置才 replace；OpenLDAP 使用已验证的密码修改机制。
4. 目录明确成功后，PG 同事务写变更时间、sync_task、outbox、审计并置 COMMITTED、解除 gate；提交后分发无口令事件并清理缓存会话。
5. 目录明确拒绝可置 REJECTED 并解除 gate，epoch 不回退。超时或目录成功后 PG 失败维持阻断并置 UNKNOWN，禁止自动重放写入，进入恢复流程。

成功返回 operation_id、changed_at 和异步任务状态；结果不明返回 202，客户端仅查询操作状态，不重复提交密码。完整状态机、数据约束与恢复证据见 [T3](tasks/T3-密码变更与失败恢复.md)。

### 3.2 密码重置

| 渠道 | 前置校验 | 说明 |
|------|---------|------|
| 自助重置 `POST /api/password/reset` | 身份验证：手机短信 OTP / 邮箱链接 / 飞书扫码，三者任选其一通过 | 分两步：`reset-apply` 返回 `reset_token`（TTL 10 分钟，一次性），`reset-confirm` 提交新密码 |
| 管理员重置 `POST /admin/users/{id}/password-reset` | 管理员权限 + 二次认证 | 生成随机初始密码，强制首登改密（`must_change_password=true`） |

### 3.3 密码策略规则（`iam_password_policy`，可按用户组覆盖）

| 规则 | 默认值 | 校验点 |
|------|--------|--------|
| 最小长度 | 10 | 字符数（含中文按 Unicode 码点计） |
| 字符类别 | ≥3 类（大写/小写/数字/符号） | 正则 + 分类计数 |
| 禁止弱口令 | 命中常见口令字典、拼音姓名、`unipass`、连续/重复 3 位以上 | 字典 + 模式匹配 |
| 不含用户名 | 是 | `new_password` 包含 `employee_no`/`sAMAccountName`/姓名拼音则拒绝 |
| 历史不可复用 | 最近 5 次 | 目录原生历史策略，不复制哈希至 IAM |
| 有效期 | 365 天，到期提前 14 天提醒 | 门户强制引导改密 |
| 锁定 | 连续 5 次失败锁 30 分钟 | 与 §7.3 限流协同 |

策略校验以规则链实现（`PasswordRule` 接口 + 顺序执行 + 收集全部违规项一次返回），避免用户逐条试错。错误码见 §8。

## 4. 同步与外部接口详细设计

### 4.1 密码变更同步接口（飞书）

飞书写密码、成员全局撤销能力尚未获得官方契约及租户实测证明，旧版 PATCH/password/force_refresh 示例撤回，不得据此实现。首期仅通过密码事件吊销 UniPass 会话，并阻止飞书身份静默绕过近期认证。外部能力探测、任务状态及替代验收见 [T5 设计](tasks/T5-飞书免登与异步任务.md)。

### 4.2 AD / 目录 Connector

当目录为外部独立 LDAP、Windows 由另一份 AD 承载时启用：以 LDAP modify 将密码写入 AD，使用 `ldaps://` + 证书固定。若 AD 即目录本身，本 Connector 自动跳过（`SKIPPED`），避免无意义写。

### 4.3 App 推送 Connector

调用企业推送网关，payload 不含任何凭证信息，仅 `{ "type": "SESSION_REVOKED", "userId": "u-10086", "reason": "PASSWORD_CHANGED", "ts": ... }`。App 侧收到即清除本地令牌并跳转登录页。推送失败不影响安全（服务端已吊销），仅记 `FAILED` 供体验优化。

### 4.4 飞书事件回调 `POST /api/connector/feishu/event`

处理流程：解密（Encrypt Key AES-256-CBC）→ 校验 `verification token` → URL _challenge 首次应答 → 事件去重（`event_id` Redis Set，TTL 1 小时）→ 落 `feishu_event_log` → 分发处理（通讯录变更：新增/异动/离职）。离职事件触发 IAM 账号禁用与全端下线。

响应必须在 3 秒内返回 200，业务处理异步化，否则飞书会判定失败并重推（重推依赖去重保证幂等）。

### 4.5 管理接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/admin/apps` | POST/PUT/GET | 客户端注册：`client_name`、`redirect_uris[]`、`grant_types[]`、`scopes[]`、`token_ttl` 覆盖、`secret`（创建时一次性返回明文，此后仅显示掩码） |
| `/admin/users/{id}/status` | PUT | 启用/禁用/解锁；禁用即刻吊销会话 |
| `/admin/sessions/{userId}` | DELETE | 强制下线指定用户 |
| `/admin/sync/retry/{taskId}` | POST | 手动重试同步任务（运维 SOP 场景 B 使用） |
| `/admin/audit` | GET | 按 `user_id`/`action`/`client_id`/时间段查询，只读，导出需二次授权 |
| `/admin/password-policy` | GET/PUT | 策略读写，变更进变更单流程 |

## 5. 数据模型

### 5.1 核心表（PostgreSQL DDL 摘要）

```sql
-- 用户（LDAP 的派生镜像 + 内部扩展字段，不含任何密码明文/哈希）
CREATE TABLE iam_user (
    id                  BIGSERIAL PRIMARY KEY,
    employee_no         VARCHAR(64)  NOT NULL UNIQUE,      -- 全局唯一标识
    ldap_dn             VARCHAR(512) NOT NULL,
    sam_account_name    VARCHAR(128),
    display_name        VARCHAR(128),
    email               VARCHAR(256),
    mobile              VARCHAR(32),
    dept_id             VARCHAR(64),
    status              VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE', -- ACTIVE/DISABLED/LOCKED/LEFT
    must_change_password BOOLEAN      NOT NULL DEFAULT FALSE,
    password_changed_at TIMESTAMPTZ,
    failed_attempts     INT          NOT NULL DEFAULT 0,
    locked_until        TIMESTAMPTZ,
    directory_etl_at    TIMESTAMPTZ  NOT NULL,
    created_at          TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_iam_user_status ON iam_user(status);
CREATE INDEX idx_iam_user_dept   ON iam_user(dept_id);

-- 外部身份映射（飞书/App/AD 的 user id ↔ IAM 用户）
CREATE TABLE iam_user_external_binding (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT NOT NULL REFERENCES iam_user(id),
    target_system VARCHAR(32) NOT NULL,     -- FEISHU / AD / APP
    external_id   VARCHAR(128) NOT NULL,
    bind_type     VARCHAR(16) NOT NULL,     -- AUTO_IMPORT / USER_CONFIRM / ADMIN
    bound_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (target_system, external_id)
);

-- 密码历史（仅哈希，用于不可复用校验）
CREATE TABLE iam_password_history (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT NOT NULL REFERENCES iam_user(id),
    password_hash VARCHAR(256) NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_pwd_hist_user ON iam_password_history(user_id, created_at DESC);

-- 同步任务（本地消息表）
CREATE TABLE sync_task (
    id            BIGSERIAL PRIMARY KEY,
    event_id      VARCHAR(64)  NOT NULL UNIQUE,   -- 幂等键
    user_id       BIGINT       NOT NULL,
    target_system VARCHAR(32)  NOT NULL,          -- FEISHU / AD / APP
    action        VARCHAR(32)  NOT NULL,          -- PASSWORD_UPDATE / FORCE_REAUTH / SESSION_REVOKED
    status        VARCHAR(24)  NOT NULL,          -- PENDING/RUNNING/SUCCESS/SUCCESS_DEGRADED/FAILED/DEAD/SKIPPED
    retry_count   INT          NOT NULL DEFAULT 0,
    last_error    VARCHAR(512),
    next_retry_at TIMESTAMPTZ,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_sync_task_pending ON sync_task(status, next_retry_at);
CREATE INDEX idx_sync_task_user    ON sync_task(user_id, created_at DESC);

-- 应用（客户端）注册
CREATE TABLE iam_app (
    id                 BIGSERIAL PRIMARY KEY,
    client_id          VARCHAR(64) NOT NULL UNIQUE,
    client_secret_hash VARCHAR(256),
    app_name           VARCHAR(128) NOT NULL,
    protocol           VARCHAR(16)  NOT NULL,     -- OIDC / SAML / CAS / RADIUS
    grant_types        VARCHAR(256) NOT NULL,
    redirect_uris      TEXT         NOT NULL,     -- 精确匹配白名单，JSON 数组
    post_logout_uris   TEXT,
    backchannel_logout_uri TEXT,
    scopes             VARCHAR(256) NOT NULL,
    token_ttl_override INT,
    is_public_client   BOOLEAN      NOT NULL DEFAULT FALSE,
    status             VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',
    owner_dept         VARCHAR(64),
    created_at         TIMESTAMPTZ  NOT NULL DEFAULT now()
);

-- 会话（Redis 为主存，DB 为可查询副本）
CREATE TABLE iam_session (
    id          BIGSERIAL PRIMARY KEY,
    session_id  VARCHAR(64) NOT NULL UNIQUE,
    user_id     BIGINT      NOT NULL,
    client_id   VARCHAR(64),
    ip          VARCHAR(64),
    user_agent  VARCHAR(256),
    device_id   VARCHAR(128),
    started_at  TIMESTAMPTZ NOT NULL,
    last_seen_at TIMESTAMPTZ NOT NULL,
    expires_at  TIMESTAMPTZ NOT NULL,
    revoked_at  TIMESTAMPTZ,
    revoke_reason VARCHAR(32)   -- PASSWORD_CHANGE / ADMIN / EXPIRED / RISK_CONTROL
);

-- 审计日志（按月分区）
CREATE TABLE audit_log (
    id         BIGSERIAL,
    user_id    BIGINT,
    action     VARCHAR(32) NOT NULL,   -- LOGIN/LOGOUT/PASSWORD_CHANGE/PASSWORD_RESET/FAILED_LOGIN/TOKEN_ISSUE/SYNC/ADMIN_OP
    result     VARCHAR(16) NOT NULL,   -- SUCCESS/FAIL/DENIED
    client_id  VARCHAR(64),
    ip         VARCHAR(64),
    detail     JSONB,                  -- 严禁含密码/完整令牌
    trace_id   VARCHAR(64),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);
```

`audit_log` 保留策略：热数据 6 个月在线可查，之后转冷存储（对象存储）归档 ≥ 12 个月，归档不可删改。

补充约束说明（开发实现须落实，运维对账依赖此行为）：

- `sync_task(event_id,target)` 联合唯一；同一事件可以投递多个目标，重复投递同一目标命中已有记录。V10 的短租约、版本确认与死信恢复见 [实现设计](23-持久同步任务与死信恢复.md)，下游调用仍为至少一次。
- 每日外部对账仍待实现：补发按 `(event_id,target)` 核对投递与最终状态，不能只按用户/日期跳过同日的新 auth_epoch；已有成功任务不等于外部当前状态已经证实。未知结果采用外部幂等键或读取核验，不宣称恰好一次。
- `iam_user` 为目录派生副本，禁止业务代码直接改其身份字段（`employee_no`/`ldap_dn`）；仅目录同步任务可写，字段更新需记录 `directory_etl_at`。
- `iam_app.redirect_uris` 为 JSON 数组、逐条精确匹配；回调地址变更须走运维 SOP §5 变更单流程，并在变更后重验开放重定向用例（§10 边界用例）。
- `audit_log.detail` 为 JSONB 但禁止包含口令与完整令牌，入库前经脱敏过滤器处理（LLD §6）。

### 5.2 缓存 Key 设计（Redis）

| Key 模式 | 内容 | TTL |
|----------|------|-----|
| `unipass:session:{sid}` | 会话对象 | 8 h 滑动 |
| `unipass:user_sessions:{userId}` | Set，会话组索引 | 与最长会话一致 |
| `unipass:code:{code}` | 授权码上下文 | 60 s |
| `unipass:token:refresh:{rt}` | refresh token 记录 | 30 d |
| `unipass:authz:{ctx}` | 授权请求上下文（state/redirect_uri） | 10 min |
| `unipass:reset:{token}` | 自助重置一次性 token | 10 min |
| `unipass:feishu:tenant_token` | 飞书租户令牌 | 值 -300 s |
| `unipass:ratelimit:authn:{ip}` / `:{account}` | 限流计数 | 60 s / 30 min |
| `unipass:feishu:event:{event_id}` | 事件去重 | 1 h |

吊销全部会话的实现：读取 `user_sessions` Set → 批量删除 session/refresh key → 更新 DB `revoked_at`。禁止使用 `KEYS`/`SCAN` 全库匹配。

### 5.3 事件契约 `unipass.password.changed`

```json
{
  "event_id": "evt-20261018-000123",
  "event_type": "unipass.password.changed",
  "occurred_at": "2026-10-18T02:15:00Z",
  "payload": {
    "user_id": "u-10086",
    "employee_no": "E10086",
    "password_changed_at": "2026-10-18T02:15:00Z",
    "change_channel": "PORTAL",
    "targets": ["FEISHU", "APP"]
  }
}
```

**新密码不进入事件体、Redis、队列、数据库或备份**。不采用短期明文中转；同步事件只负责会话撤销与通知。飞书外部能力以 T5 实测矩阵为准。

## 6. 安全细节实现约定

- **PKCE**：`code_verifier` 43–128 字符，仅 `S256`；无 PKCE 的公共客户端注册直接拒绝。
- **state / nonce**：由 SDK 生成并存储于会话，回调时严格比对；不一致直接终止并上报 `STATE_MISMATCH`。
- **Cookie**：`HttpOnly; Secure; SameSite=Lax; Path=/`；会话 Cookie 名称 `UNIPASS_SSO`。跨应用免登通过 OIDC 重定向复用 IAM 主机会话，禁止通过 URL 传递会话标识。
- **令牌绑定**：refresh token 与 `device_id` + 用户代理指纹弱绑定，异地使用触发风险审计。
- **密钥轮换**：JWKS 同时暴露 `k2026q3`/`k2026q4`，新签用 current kid，验证按 kid 选择；轮换周期 ≤ 180 天。
- **日志脱敏**：统一过滤器屏蔽 `password`、`old_password`、`new_password`、`code`、`access_token`、`refresh_token`、`client_secret` 字段值。
- **SQL/LDAP 注入**：LDAP 过滤器一律使用目录客户端库的参数化模板（`{0}` 占位 + RFC 4515 转义），禁止字符串拼接。
- **CORS**：门户与管理台按域名白名单，禁止 `*` 与凭证组合。

## 7. 各端接入详细设计

### 7.1 Windows

| 项 | 设计 |
|----|------|
| 域内登录 | 复用 AD/Kerberos，无需部署组件；IAM 通过 LDAP 扩展操作写 AD 密码 |
| 域外/浏览器 | AD FS → IAM SAML IdP；声明映射 `employeeNumber → name-id` |
| 凭证提供程序 | `unipass-sdk-windows`（C++/C# 实现 `ICredentialProvider`），在线时 LDAP bind，离线按本地缓存策略放行 |
| 组策略 | 受信任站点、自动登录、锁屏后要求重新认证（配合会话 TTL） |
| 证书 | AD FS 签名/加密证书默认 1 年，到期前 60 天告警 |

### 7.2 移动端 SDK（`unipass-sdk-mobile`）

对外 API：

```
login(hostActivity)                     // 拉起系统浏览器/AUTH 会话完成授权码+PKCE
isLoggedIn(): Boolean
getValidAccessToken(force = false): String   // 过期自动 refresh，失败则触发重新登录
clearTokens()
handleChangePasswordEntry()             // 跳转统一改密页
```

要求：令牌存 iOS Keychain（`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`）/ Android EncryptedSharedPreferences；禁止 WebView 内输入密码（避免中间人），登录页必须由系统浏览器或 ASWebAuthenticationSession/Custom Tab 承载；监听推送 `SESSION_REVOKED` 即清本地令牌。

### 7.3 门户前端（`unipass-portal`）

页面：登录页（账号密码 / 飞书扫码 / OTP 二次验证）、强制改密页（首次登录或到期）、自助重置三步页、会话列表页（查看并下线其他设备）。

登录页流程要点：失败提示统一为"账号或密码错误"，不区分账号不存在与密码错误（防账号枚举），仅在账号锁定后明示锁定与解锁途径；密码复杂度在前端做即时校验提示，但服务端为唯一权威。

### 7.4 防暴力破解细节

| 层级 | 触发条件 | 动作 |
|------|---------|------|
| L1 | 同账号 3 次失败 | 出现图形/滑块验证码 |
| L2 | 同账号 5 次失败 | 锁定 30 分钟，记 `LOCKED` |
| L3 | 同 IP 20 次失败/分钟 | IP 临时封禁 10 分钟 |
| L4 | 撞库特征（多账号同一 IP） | 告警 + 全局挑战 |

## 8. 错误码定义

| Code | HTTP | 标识 | 含义 | 处理建议 |
|------|------|------|------|---------|
| 0 | 200 | OK | 成功 | — |
| 40001 | 400 | INVALID_REQUEST | 参数缺失/非法 | 检查必填参数 |
| 40002 | 400 | REDIRECT_URI_MISMATCH | 回调地址不匹配 | 应用注册处核对白名单 |
| 40101 | 401 | INVALID_CREDENTIAL | 账号或密码错误 | 统一文案，不区分原因 |
| 40102 | 401 | INVALID_CODE | 授权码无效或已使用 | 重新发起授权 |
| 40103 | 401 | INVALID_CLIENT | 客户端鉴权失败 | 核对 client_id/secret |
| 40104 | 401 | MFA_REQUIRED | 需要二次验证 | 按服务器 context 创建并验证绑定挑战，再重试原授权；不在授权请求夹带 OTP |
| 40105 | 401 | TOKEN_REVOKED | 令牌已失效 | 重新登录 |
| 40106 | 401 | STALE_TOKEN | 令牌签发早于最近改密时间 | 重新登录（`pwd_ver` 校验） |
| 40301 | 403 | FORBIDDEN_ADMIN | 管理接口权限不足 | 申请角色 |
| 41001 | 400 | PASSWORD_TOO_WEAK | 不满足复杂度 | 返回违规规则列表 |
| 41002 | 400 | PASSWORD_IN_HISTORY | 命中历史密码 | 换一个 |
| 41003 | 400 | PASSWORD_CONTAINS_IDENTITY | 含姓名/工号/邮箱 | 换一个 |
| 41004 | 400 | OLD_PASSWORD_INCORRECT | 旧密码错误 | 计入失败次数 |
| 42001 | 423 | ACCOUNT_LOCKED | 账号锁定 | 提示解锁时间/联系管理员 |
| 42002 | 403 | ACCOUNT_DISABLED | 账号已禁用 | 联系管理员 |
| 42003 | 403 | PASSWORD_EXPIRED | 密码过期需修改 | 强制引导改密页 |
| 43001 | 429 | RATE_LIMITED | 触发限流 | 退避重试 |
| 50001 | 500 | INTERNAL_ERROR | 服务内部错误 | 按 trace_id 排查 |
| 50002 | 503 | DIRECTORY_UNAVAILABLE | 目录不可用 | 熔断 + 切换从/主 |
| 51001 | 502 | SYNC_TARGET_ERROR | 下游系统返回错误 | 查 `sync_task.last_error` |
| 51002 | 502 | SYNC_PERMISSION_DENIED | 下游权限不足（含飞书权限回收） | 走降级或补权限 |

`trace_id` 必须回传前端并写入日志，作为验收与故障定位的唯一线索。

## 9. 异常与重试策略

| 依赖 | 超时 | 重试 | 降级 |
|------|------|------|------|
| LDAP bind/modify | 3 s / 5 s | 不重试（写操作幂等性风险） | 从节点不可用则拒绝改密并告警 |
| PostgreSQL | 3 s | 1 次 | 无（核心数据源） |
| Redis | 500 ms | 1 次 | 会话不可用则要求重新登录，不降级为放行 |
| 飞书 API | 5 s | 指数退避 1/5/15 分钟，3 次 | 转 `SUCCESS_DEGRADED`（强制重认证） |
| App 推送 | 3 s | 2 次 | 放弃（服务端已吊销） |
| 事件总线 | 2 s | outbox 补偿扫描（每 30 秒） | 不丢消息 |

熔断：目录连续失败 20 次/30 秒触发熔断 30 秒，熔断期间登录直接返回 503 并展示维护页，禁止"默认放行"式降级。

## 10. 单元与集成测试要点

- 授权码一次性：同一 code 二次兑换必须 `INVALID_CODE`。
- PKCE 缺失/校验失败/`plain` 提交三种情况均拒绝。
- `redirect_uri` 前缀匹配、大小写、尾部斜杠、端口差异 4 组边界用例。
- 改密后：旧 access token 在有效期内必须被拒（`STALE_TOKEN`）、旧 refresh 必须被拒、Windows 用新密码可登录。
- 飞书写密码失败 → 必须降级为 `SUCCESS_DEGRADED` 且不阻断改密接口返回。
- 密码规则：每种违规项至少 1 条正反用例，覆盖中文口令与 emoji。
- 限流与锁定：L1–L4 逐级触发与恢复。
- 事件重复投递：同一 `event_id` 二次消费不产生第二次下游调用（幂等验证）。
- 日志脱敏断言：捕获日志输出，断言不含明文密码与完整令牌。
