# 审计字段级脱敏（AUDITOR）

> 本增量让只读审计员（`ROLE_ADMIN_AUDIT`）看到脱敏后的审计视图；`ROLE_SYSTEM_ADMIN` 保留完整字段用于排障与追责。状态为**编码增量**，仅由远程 CI 验证。

## 1. 策略

| 字段 | AUDITOR（仅 `ROLE_ADMIN_AUDIT`） | SYSTEM_ADMIN |
|---|---|---|
| `source_ip` | IPv4 掩码到 `/24`；IPv6 掩码到 `/48`；非法/主机名 → `redacted` | 原值 |
| `detail.login` | 删除（不返回键） | 原值 |
| `detail` 其它白名单键（role/reason/client_id/kind/window_seconds 等） | 保留 | 保留 |
| `subject`/`client_id`/`operation_id`/`action`/`result` | 保留 | 保留 |
| CSV `source_ip` | 同上掩码 | 原值 |

- 脱敏在读取投影层完成，不改写数据库；原始审计行保持完整，便于 SYSTEM_ADMIN 复核。
- 角色判断读取 `iam_user_role` 实时行（`AdminConsoleService.isSystemAdmin`），不信任会话 roles。
- 同一账户若同时持有 SYSTEM_ADMIN 与 AUDIT，按 SYSTEM_ADMIN 处理（完整视图）；持有 AUDIT 但无 SYSTEM_ADMIN 时脱敏。
- `detail.login` 是登录标识而非动作主体；移除它不影响 `operator`（actor UUID）与 `subject` 的追责链。

## 2. 实现

- `AdminAuditService.redact(Entry)`：复制 detail、删除 `login`、掩码 `source_ip`。
- `AdminAuditService.maskSourceIp(String)`：IPv4 取前三段 + `.0/24`；IPv6 取前三组 + `::/48`；其他返回 `redacted`；null 保持 null。
- `AdminAuditService.export(cap, redact)`：CSV 的 `source_ip` 使用同一掩码；旧 `export(cap)` 保持完整导出（内部/测试）。
- `AdminConsoleController`：`GET /audit` 对非 SYSTEM_ADMIN 逐条 `redact`；`GET /audit/export` 传 `redact`。
- 未新增迁移；无 API 形状变化（只改变字段值/键的存在性）。

## 3. 测试

- `AdminConsoleIT.auditorRedactionMasksAddressAndDropsLogin`：IPv4 `/24`、IPv6 `/48`、非法地址 `redacted`、`login` 被移除、原 Entry 不被改写。
- `ClientManagementHttpIT.auditorSeesRedactedAuditWhileSystemAdminSeesFullDetail`：SYSTEM_ADMIN 的 JSON 含完整 IP 与 `login`；切为 AUDIT 后 JSON 含 `203.0.113.0/24`、不含完整 IP/`login`；CSV 同样掩码。
- 既有审计分页/导出/游标测试保持。

## 4. 边界与未做

- 只对 `source_ip` 与 `detail.login` 做字段级脱敏；`subject`/`client_id` 等仍为原值。
- 未做按租户/字段策略配置、审计查看水印、跨库冷存储/时间分区/多实例选举/回退演练（docs/32 N3 其余项）。
- 脱敏是读取投影，不阻止 SYSTEM_ADMIN 查看原值，也不改变 CSV 行数上限。
