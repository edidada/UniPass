## 1. 部署前准备

### 1.1 环境要求（生产规格）

| 组件 | 规格 | 数量 | 说明 |
|------|------|------|------|
| IAM 应用节点 | 8C16G，CentOS 7.9 / Rocky 9 | 2 | 主备 / 负载均衡 |
| LDAP / AD | 4C8G，SSD 200G | 2 | 主从复制 |
| Redis（会话） | 4C8G | 3 | Sentinel |
| PostgreSQL | 8C16G，SSD 500G | 2 | 主从流复制 |
| Nginx / LB | 4C8G | 2 | 双活 + VIP/VRRP |

测试环境按生产规格的 1/4 缩减，但组件种类与版本必须一致；Windows 集成线在测试环境需保留一台域控 + 一台加域客户机，否则 A2 验收项无法验证。

### 1.2 端口与网络策略

| 源 | 目标 | 端口 | 用途 |
|------|------|------|------|
| 终端 | Nginx VIP | 443 | HTTPS 入口（80 仅做 301 跳转） |
| Nginx | IAM 节点 | 8080 | 应用回源 |
| IAM 节点 | LDAP | 389 / 636 | 目录读写（生产强制 636 ldaps） |
| IAM 节点 | Redis | 6379 / 26379 | 会话 / Sentinel |
| IAM 节点 | PostgreSQL | 5432 | 业务库 |
| IAM 节点 | 飞书开放平台 | 443 | Connector 出站（需公网白名单） |
| Windows 客户机 | 域控 | 88 / 389 / 636 / 445 | Kerberos / LDAP / SMB |
| 监控 | 各节点 | 9090 / 9100 | Prometheus 指标采集 |

出站方向：仅 `unipass-sync` 需要访问飞书域名，其余服务可全部置于无公网环境，降低暴露面。

### 1.3 前置检查清单

- [ ] 所有节点时间同步至同一 NTP 源，偏差 < 1 秒（Kerberos 对时钟偏差敏感，超 5 分钟即认证失败）。
- [ ] DNS 可正向/反向解析所有节点，`pass.corp.example.com` 与 `iam.corp.example.com` 已指向 VIP。
- [ ] 证书就绪：通配或 SAN 证书，包含上述两个域名 + 各节点名。
- [ ] JDK 17+ 已安装，`unipass` 服务账号已创建（非 root 运行）。
- [ ] 快照/备份可用：变更窗口前对全部数据节点打快照。

## 2. 部署拓扑

```
[Internet/内网] → [Nginx LB :443]
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
   [IAM Node 1]                  [IAM Node 2]
          │                           │
          └─────────────┬─────────────┘
                        ▼
              [LDAP Master] ←→ [LDAP Slave]
                        │
              [Redis Sentinel Cluster]
                        │
              [PostgreSQL Primary/Standby]
```

逻辑上分为三个网络区：DMZ（Nginx + 静态门户）、应用区（IAM + sync + admin API）、数据区（LDAP/Redis/PG）。跨区访问只允许应用区主动发起。

## 3. 部署步骤

### 步骤 1：目录服务初始化

**（a）自建 OpenLDAP**

```bash
# 安装（Rocky 9）
dnf install -y openldap-servers openldap-clients

# 初始化配置
cp /usr/share/openldap-servers/DB_CONFIG.example /var/lib/ldap/DB_CONFIG
chown ldap:ldap /var/lib/ldap/DB_CONFIG
systemctl enable --now slapd

# 设置管理员口令
ldappasswd -s "${LDAP_ADMIN_PW}" | sed "s#/##;s/^/olcRootPW /" # 写入 cn=config
```

**（b）对接现有 AD**：跳过安装，仅需创建 IAM 专用绑定账号（最小权限，只读 + 改密目标 OU 的写权限），并确认 636 端口可用。

后续统一动作：

- 导入 Base DN：`dc=corp,dc=example,dc=com`，创建 `ou=users`、`ou=groups`。
- 从 HR 系统批量导入用户，`employeeNumber` 设为唯一属性。
- 启用索引：`employeeNumber`、`sAMAccountName`、`uid`、`mail`。
- 启用主从复制（`syncrepl`/Replication Agreements），验证从节点数据一致。
- 强制 ldaps：`olcTLSVerifyPeer`，禁用匿名绑定 `olcAccess to * by * none`。

导入后核对：`ldapsearch` 记录数 = HR 在职人数（差异需给出原因清单）。

### 步骤 2：数据库与 Redis

```bash
# PostgreSQL
createuser -SDRP unipass
createdb -O unipass unipass
# 执行 flyway migrate（见步骤 3）

# Redis Sentinel：3 节点，quorum=2
# redis.conf 关键项
appendonly no            # 会话数据允许丢失，不持久化
maxmemory 4gb
maxmemory-policy allkeys-lru
```

Redis 仅承载会话与临时授权码，容量按在线用户数 × 平均会话大小估算，预留 3 倍余量。

### 步骤 3：IAM 应用部署

```bash
useradd -r -m -s /bin/bash unipass
tar -xzf unipass-iam-1.0.0.tar.gz -C /opt/unipass/
cd /opt/unipass/unipass-iam
./bin/flyway.sh migrate          # 数据库迁移
systemctl enable --now unipass-iam
```

`application.yml` 关键配置（口令一律从环境变量/KMS 注入，不落盘明文）：

```yaml
unipass:
  ldap:
    url: ldaps://ldap-master.corp.example.com:636
    base-dn: dc=corp,dc=example,dc=com
    bind-dn: cn=iam-bind,ou=service,dc=corp,dc=example,dc=com
    bind-password: ${UNIPASS_LDAP_BIND_PW}
    user-search-base: ou=users
    user-search-filter: (employeeNumber={0})
  datasource:
    url: jdbc:postgresql://pg-primary.corp.example.com:5432/unipass
    username: unipass
    password: ${UNIPASS_DB_PW}
  redis:
    sentinel:
      master: unipass-session
      nodes: redis-1:26379,redis-2:26379,redis-3:26379
    password: ${UNIPASS_REDIS_PW}
    key-prefix: "unipass:session:"
  oidc:
    issuer: https://pass.corp.example.com
    access-token-ttl: 3600
    refresh-token-ttl: 2592000
    signing-key:
      kid-current: k2026q4
      private-key-ref: kms://unipass/jwt/k2026q4
  event:
    password-changed-topic: unipass.password.changed
```

服务以 systemd 托管（`/etc/systemd/system/unipass-iam.service`），以 `unipass` 账号运行、限制核心转储、`EnvironmentFile` 注入口令。

启动后逐节点验证：

```bash
curl -sk https://iam-node1:8080/actuator/health     # {"status":"UP"}
curl -sk https://pass.corp.example.com/.well-known/openid-configuration
```

第二条必须返回完整的 issuer、authorization_endpoint、token_endpoint、jwks_uri，且 `issuer` 与配置值**字符串完全一致**，否则各端 SDK 校验会失败。

### 步骤 4：Windows 集成

**模式 A — 已有 AD，IAM 直接对接（推荐）**

IAM 以 AD 为目录，Windows 登录不经过 IAM，改密通过 LDAP `Modify Password Extended Operation`（`1.3.6.1.4.1.4203.1.11.1`）写入 AD。此模式无需额外部署组件，仅需确认绑定账号具备目标 OU 的"重置密码"权限。

**模式 B — AD FS 联合**

- 在 Windows Server 上安装 AD FS 角色，加入 farms。
- 配置信赖方信任（Relying Party Trust），指向 IAM 的 SAML 元数据 URL：`https://pass.corp.example.com/saml/metadata`。
- 配置 AD FS 声明规则，将 `employeeNumber` 映射为 `name-id`。
- 通过组策略推送"IE/Edge 受信任站点"与"自动登录"策略，实现域内浏览器免输密码。
- 验证：非域设备访问内网应用时，被引导至 AD FS → IAM 登录页并可正常回跳。

**模式 C — 非域环境**

部署 LDAP + Winlogon 凭证提供程序（`unipass-sdk-windows`），使 Windows 登录校验指向统一目录。注意该模式要求本地缓存凭证策略配置，断网场景需明确是否允许登录。

### 步骤 5：飞书集成

- 在飞书开放平台创建"企业自建应用"，获取 `App ID` / `App Secret`。
- 配置 IAM 的飞书 Connector：填写 App 凭证、通讯录同步范围（受限可见部门）、事件订阅 URL `https://pass.corp.example.com/api/connector/feishu/event`。
- 申请权限：`contact:user.base:readonly`、`contact:user.employee_id:readonly`；若需写密码，另行申请通讯录写权限（**多数租户不可批**，需按架构文档 §10 降级为强制重新认证）。
- 配置事件订阅密钥校验（`verification token`），并对 Encrypt Key 做 AES 解密。
- 首次全量拉取通讯录，写入 `iam_user_external_binding` 映射表；此后每日增量对账。

### 步骤 6：负载均衡与 TLS

```nginx
upstream iam_cluster {
    server 10.0.10.11:8080 max_fails=2 fail_timeout=10s;
    server 10.0.10.12:8080 max_fails=2 fail_timeout=10s;
    health_check interval=5s fails=2 passes=3;   # nginx_upstream_check_module
    keepalive 64;
}

server {
    listen 443 ssl http2;
    server_name pass.corp.example.com iam.corp.example.com;

    ssl_certificate     /etc/nginx/tls/unipass.pem;
    ssl_certificate_key /etc/nginx/tls/unipass.key;   # chmod 600
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;

    location / {
        limit_req zone=auth burst=20 nodelay;   # 认证接口限流
        proxy_pass http://iam_cluster;
        proxy_set_header X-Real-IP        $remote_addr;
        proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

强制 HTTPS，HSTS 开启，TLS 1.2+。`X-Forwarded-Proto` 必须透传，否则应用生成的 OIDC 回调地址会变成 http 导致跳转失败。

### 步骤 7：监控与日志接入

- 部署 `node_exporter`、应用暴露 `/actuator/prometheus`。
- 导入 UniPass 监控面板与告警规则（阈值见运维 SOP §3）。
- 审计日志双写：数据库 + 集中日志系统（filebeat/rsyslog），后者用于满足 ≥6 个月留痕要求。

## 4. 部署后冒烟验证

| 编号 | 验证项 | 方法 | 预期 |
|------|--------|------|------|
| S1 | 健康检查 | `curl /actuator/health` 两节点 | `UP` |
| S2 | OIDC 发现 | `GET /.well-known/openid-configuration` | 200，issuer 匹配 |
| S3 | 授权码流程 | 浏览器访问测试应用登录 | 成功回跳并显示身份 |
| S4 | 改密生效 | 修改测试账号密码 | 旧密码立即登录失败 |
| S5 | 会话吊销 | 改密后访问已登录应用 | 被重定向至登录页 |
| S6 | 飞书同步 | 改密后查 `sync_task` | 记录状态 = success |
| S7 | Windows 域登录 | 测试机用新密码登录 | 成功 |
| S8 | LB 摘流 | 停一个 IAM 节点 | 服务不中断，节点被摘除 |

S1–S8 全部通过方可进入集成测试阶段（对应 PM 文档 T9）。

## 5. 回滚方案

| 场景 | 回滚动作 | 数据影响 |
|------|---------|---------|
| 应用版本缺陷 | 切回上一版本包，`flyway repair` + `flyway migrate` 至上一标记 | 数据库迁移脚本需保持向后兼容（只加列不删列） |
| 配置错误 | 恢复变更前 `application.yml` 备份并重启 | 无 |
| 目录变更失败 | 从 LDAP slave/备份恢复 `cn=config` 与数据 LDIF | 可能回退部分账号 |
| 全量上线失败 | LB 切回旧登录入口（保留 4 周） | 无，旧系统未下线 |

发布采用蓝绿：新版本先在 1 个节点灰度 10% 流量，观察 30 分钟无异常再全量。旧登录入口在全量后保留 4 周用于回退，第 5 周关闭（对应里程碑 M5）。
