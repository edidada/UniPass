## 1. 验收组织与前置条件

**参与方**：项目组（PM/架构/开发）、QA、运维、业务方代表（应用 Owner）、安全工程师、员工代表（试用反馈）。

**前置条件**（不满足则验收顺延，不开会）：

- [ ] 部署文档 §4 冒烟项 S1–S8 全部通过并有执行记录。
- [ ] 验收环境（预生产）配置与生产一致，含 AD 域控与加域客户机各 1 台以上。
- [ ] 验收账号就绪：普通员工 ×3、部门管理员 ×1、系统管理员 ×1、离职模拟账号 ×1、锁定测试账号 ×1；已绑定飞书与 App。
- [ ] 试点应用就绪：PC Web ×1（OIDC）、传统系统 ×1（CAS，可选）、App ×1（PKCE）、飞书工作台应用 ×1。
- [ ] 缺陷库中无遗留 P1/P2 缺陷，P3 缺陷有明确修复批次。

## 2. 功能验收 checklist

| 序号 | 验收项 | 通过标准 | 验证方式 |
|------|--------|---------|---------|
| A1 | PC Web 单点登录 | 登录 IAM 后，访问接入的 OA/CRM 无需二次输入密码 | 手工演示 |
| A2 | Windows 桌面登录 | 域内用户用统一密码登录 Windows，密码与 IAM 一致 | 域内机器实测 |
| A3 | 飞书免登 | 飞书工作台打开应用，自动识别 IAM 身份 | 飞书客户端实测 |
| A4 | 移动 App 登录 | 使用 IAM 账号密码或生物识别（本地解锁）完成登录 | 真机测试 |
| A5 | **密码一处修改** | 在 PC Web 修改密码后，飞书/App 下次请求被强制重新认证；Windows 新登录使用新密码 | 端到端验证 |
| A6 | 密码策略 | 弱密码被拒绝，历史密码不可复用 | 接口测试 |
| A7 | 审计日志 | 登录、登出、密码变更可查询，保留 ≥6 个月 | 控制台抽查 |
| A8 | 高可用 | 单节点故障，认证服务在 30 秒内恢复 | 演练报告 |

### 2.1 详细测试用例（关键项）

**A1 — PC Web 单点登录**

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 浏览器访问 CRM 受保护页面 | 302 到 IAM 登录页，URL 含 `state`、`code_challenge`（Web 与 App 均启用 S256 PKCE） |
| 2 | 输入统一账号密码 | 回跳 CRM 且已登录，展示当前身份 `employee_no` |
| 3 | 新标签页访问 OA（同样已接入） | **不出现登录页**，直接进入（核心 SSO 判据） |
| 4 | 检查浏览器 Cookie | 会话 Cookie 为 `HttpOnly Secure SameSite=Lax` |
| 5 | 篡改 `redirect_uri` 重放授权请求 | 返回 400，不发生重定向 |

**A2 — Windows 桌面登录**：先用旧密码登录成功 → 通过门户改密 → 锁屏 → 用新密码解锁/重新登录成功 → 用旧密码登录失败。若为模式 B（AD FS），额外验证非域设备经表单登录可访问内网应用。

**A3 — 飞书免登**：飞书工作台点击应用 → 未出现账号密码输入即进入应用；若首次使用则出现一次绑定引导，绑定后重启飞书再次进入应免登。同时验证 IAM 会话失效后再次打开应用要求重新认证（不允许静默放行）。

**A4 — 移动 App 登录**：账号密码登录（走系统浏览器 ASWebAuthenticationSession/Custom Tab，非内嵌 WebView）→ 关闭 App 重开仍登录（refresh 生效）→ 生物识别解锁本地。iOS/Android 各 1 台真机，含 1 台低版本系统。

**A5 — 密码一处修改（本项目核心，必须端到端逐端取证）**

| 检查点 | 操作 | 预期 | 时限 |
|--------|------|------|------|
| A5-1 | PC Web 修改密码 | 接口返回成功，`password_changed_at` 更新 | 即时 |
| A5-2 | 用改密前的 access_token 调用业务 API | 返回 `40106 STALE_TOKEN` | ≤ 5 s |
| A5-3 | 用改密前的 refresh_token 刷新 | 返回 `40105 TOKEN_REVOKED` | ≤ 5 s |
| A5-4 | 已登录的 Web 应用发起请求 | 被重定向至 IAM 登录页 | ≤ 5 s |
| A5-5 | 飞书端 | 下次访问应用要求重新认证（或飞书侧密码已更新） | P95 ≤ 30 s，P99 ≤ 5 min |
| A5-6 | App 端 | 收到 `SESSION_REVOKED` 推送并清除本地令牌，回到登录页 | ≤ 60 s；推送失败时下次请求仍被拒（安全兜底） |
| A5-7 | Windows | 新登录必须使用新密码 | 即时（同一目录） |
| A5-8 | 旧密码 | UniPass 在线认证及可控 AD 在线新登录均拒绝；外部凭证与离线缓存按设计基线单列范围 | 即时 |

取证要求：每个检查点记录时间戳与 `trace_id`，计算实测延迟；A5-5 的尾延迟报告按 T9 设计采集至少 1000 个合规样本并记录窗口及算法；10 次仅作冒烟。

**A6 — 密码策略**：逐条构造违规口令（长度不足、字符类别不足、含工号/姓名、命中字典、连续重复、命中历史 5 次内），断言返回 `41001/41002/41003` 且提示具体违规项；合规口令通过。验证锁定：连续 5 次错误密码 → `42001`，30 分钟后自动解锁；管理员可手工解锁。

**A7 — 审计日志**：登录成功/失败、登出、改密、管理员重置、强制下线、应用注册六类操作均可按 `user_id` + 时间段检索到，字段含 `action/result/client_id/ip/trace_id`；抽查 20 条确认**无密码明文与完整令牌**；验证 6 个月前数据仍可在线查询、更早数据可从归档恢复。

**A8 — 高可用演练**：演练矩阵见 §4.2。

## 3. 非功能验收

| 项 | 标准 | 方法 |
|----|------|------|
| 认证 P99 延迟 | ≤ 300 ms | 压测（峰值 50 次认证/秒，持续 10 分钟） |
| 改密 P99 | ≤ 800 ms | 压测（100 并发改密） |
| 可用性 | ≥ 99.9%（观察期内） | 灰度期监控统计 |
| 容量余量 | 支撑 2 倍峰值 | 100 次/秒压测无错误率上升 |
| 安全 | 高危 0、中危已闭环 | 渗透测试报告 + 复测 |
| 等保三级 | 身份鉴别、访问控制、安全审计、剩余信息保护条款符合 | 符合性说明 + 证据 |
| 兼容性 | Chrome/Edge/Safari 最新两版；iOS ≥ 14，Android ≥ 10 | 兼容矩阵回归 |

**渗透测试范围**：授权码截获与重放、PKCE 绕过、开放重定向、CSRF（state 缺失）、账号枚举、撞库与限流有效性、越权（普通用户调用 admin API）、令牌篡改与 `alg=none`、JWT 密钥误用、会话固定、日志泄露口令、LDAP 注入。

## 4. 可靠性与故障演练

### 4.1 故障场景验收（与运维 SOP 场景一一对应）

| 场景 | 注入方式 | 通过标准 |
|------|---------|---------|
| IAM 单节点宕机 | `systemctl stop` 节点 1 | 无请求失败（LB 5 s 内摘除），恢复后自动加入 |
| LDAP 主节点宕机 | 停主 + 从提升 | 登录可用；改密在切换完成后 ≤ 5 分钟内恢复；无数据丢失 |
| Redis 主节点宕机 | 停 Redis master | Sentinel 30 s 内完成切换；切换期间登录允许短暂重新认证，禁止绕过鉴权放行 |
| 飞书 API 不可用 | 阻断出站域名 | 改密接口仍返回成功；任务进入 `FAILED` 重试；恢复后自动补齐；对账任务不重复写 |
| 事件总线积压 | 暂停 `unipass-sync` | `sync_task` 无丢失；恢复后全部消费；积压告警触发 |
| PostgreSQL 主从切换 | 触发 failover | 认证读路径不中断；改密写路径在 30 s 内恢复 |

### 4.2 数据一致性核对

抽样 100 名员工：目录 DN ↔ `iam_user` ↔ 飞书绑定 ↔ 已发放令牌数量四方可对账，无孤儿账号；随机 10 名离职模拟账号确认已禁用且全端下线。

## 5. 缺陷分级与放行标准

| 级别 | 定义 | 放行要求 |
|------|------|---------|
| P1 致命 | 认证不可用、密码同步失效、安全绕过、数据错乱 | 必须全部关闭 |
| P2 严重 | 单端无法登录、A1–A8 任一未通过、性能不达标 | 必须全部关闭 |
| P3 一般 | 提示文案、非核心交互瑕疵 | 关闭 ≥ 90%，剩余须有修复批次与 Owner |
| P4 建议 | 优化项 | 记录进二期需求池 |

**放行结论**分三种：通过 / 有条件通过（列明条件与期限，须 PM + 安全 + 业务方共同签字）/ 不通过（回退至上一里程碑）。
