# 技术选型与决策记录

版本 V1.2，2026-10-21；状态：实施中，部分本地 PoC 已执行，外部环境和设计评审仍待完成。具体交付与验证见 [阶段进度](10-阶段实施进度.md)，下述建议不等同于部署验收。

## 1. 选择原则与决策权限

优先满足目录权威性、标准协议互通、五秒内吊销和可恢复改密，再考虑开发与运维成本。首期按 5000 员工、50 次认证/秒设计，以两倍峰值验证。架构师负责技术建议，安全负责风险审查，PM 负责范围与成本确认；未决能力不进入承诺范围。

## 2. 技术选项对比

| 决策 | 选项与取舍 | 建议 | 验证及切换条件 |
|---|---|---|---|
| ADR-01 协议引擎 | Spring 授权服务器易融入 Java 领域逻辑；Keycloak 作为独立 IdP 可减少协议实现但引入管理和扩展边界；完全自研协议成本与安全风险高 | Java 业务模块 + 成熟 Spring OAuth/OIDC 能力，禁止自行实现协议核心 | T2 PoC 覆盖发现、PKCE、刷新轮换、注销、目录联邦；若 SAML IdP 需求无法在预算内满足，整体验证独立 IdP 路线，不能两套引擎各管一份用户密码 |
| ADR-02 Java 工程 | 多仓多服务发布独立但联调复杂；单仓模块化便于当前团队维护 | 单仓 Maven 多模块为主，Gradle 在独立构建分支提供；IAM 与 sync 可独立进程，门户与管理台独立构建 | 按工程约定统一 JDK 17 LTS；Spring Boot/Security 使用同一官方 BOM 兼容组合，T2 冻结具体补丁及支持周期，提交锁定清单；本文不声称任何版本为当前最新 |
| ADR-03 目录 | AD 原生满足 Windows 域；OpenLDAP 支持非域统一身份但不能替代域控 | 有 Windows 域场景优先复用 AD；OpenLDAP 是独立部署分支 | T1 验证 LDAPS、策略、历史、复制和最小权限；无 AD 则调整 T4 范围，不默认开发 Credential Provider |
| ADR-04 业务存储 | PostgreSQL 提供事务、唯一约束、JSONB；MySQL 可实现但需另写方言与迁移 | PostgreSQL；不承诺双数据库兼容 | Flyway 管理迁移，CI 使用同版本 PG；主版本和镜像摘要在 T1 环境清单冻结 |
| ADR-05 会话与状态 | Redis 快但故障切换可能丢最近写入；PG 持久状态可控制安全版本 | Redis 存临时会话，PG 存 auth_epoch、gate、刷新族与任务 | Redis 丢失视为重新认证，不能复活令牌；关键鉴权状态以 PG 为准，缓存上限五秒，查询失败拒绝放行 |
| ADR-06 异步事件 | Kafka/RabbitMQ 提供独立消息系统但增加集群成本；PG 任务表足够当前低频改密 | 首期 PG outbox + 租约 Worker，不额外部署消息代理 | 当持续积压不能满足 SLA，压测定位为队列瓶颈后引入 broker；保留 outbox，不能靠内存事件保证不丢 |
| ADR-07 前端 | Vue/React 均可；BFF 可减少浏览器 token 暴露 | 建议 Vue 3 + TypeScript，Web 接入采用 BFF；具体依赖在 T7 锁定 | 验证 Cookie、CSRF、跨域回跳、浏览器兼容；团队已有稳定 React 基座可等价替换，不改变认证契约 |
| ADR-08 密码同步 | 明文中转难以保证日志、备份和失败重试的保密性；应用会话撤销无需保存口令 | 禁止明文中转；统一目录改密 + UniPass 会话撤销 | 飞书外部密码写入与全局撤销不预设存在；T5 实测确认后再变更范围 |
| ADR-09 审计监控 | 单机日志便宜但检索与保留不足；集中日志与指标便于取证 | 结构化日志、Micrometer 指标、Prometheus/Grafana 或企业现有平台 | T8 验证脱敏和六个月归档恢复，T11 验证告警路由；不以安装监控组件代替告警演练 |
| ADR-10 Web 后端退出 | live 状态检查能拒绝数据但不主动删除 RP 会话；内存通知队列重启会丢任务；PG 事务任务表可复用现有存储；外部 broker 增加集群成本 | PG 同事务入队与有限租约重试；Nimbus 签名/验签，RP Redis Lua 原子消费 jti、按 sid 清会话及保留吊销标记；live 检查继续保留 | 2026-10-20 已编码，见 [退出通知设计与证据](21-OIDC后端退出通知.md)。机密 Web RP 显式登记同源 URI，sid 为必填接入配置；单族退出后重新认证防止旧 sid 复用，容量与主备仍需实测 |
| ADR-11 MFA 加密主 key | 直接替换单 key 不能读旧因素；逐个尝试 key 难以核对引用及退役；只用本地 active 配置会使混合节点写回旧 key；KMS 增加外部服务依赖 | V2 带 key id 且认证 id/owner，V1 兼容；PG writer/指纹/退役控制与数据库写保护；CLI 分批重加密及验密，不改变 TOTP 秘密、时间步或 epoch | 2026-10-21 已编码，见 [设计和发布流程](22-MFA加密主密钥轮换.md)。需先全部署可读 key，再激活；退役要求无引用且验密通过。KMS、备份恢复及规模演练仍待交付 |
| ADR-12 同步确认与死信 | 内存重试不能保留宕机任务；持行锁调用外部会扩大故障；仅按任务 ID 回写会被旧 worker 覆盖；无限线程无法约束失控适配器 | PG 同事务 fan-out、短租约 owner/token/version、事务外有限调用与带版本确认；有限尝试后死信，人工重排同事务审计；缺失能力明确 BLOCKED | 2026-10-21 基础设施已编码，见 [状态机与恢复](23-持久同步任务与死信恢复.md)。不声明外部恰好一次；生产投递适配器、外部对账和告警路由仍未交付 |
| ADR-13 飞书身份接入 | 自动邮箱匹配可能误绑定；内存 state 无法跨节点单次消费；旧版 OAuth 不自动兼容新版 PKCE；永久能力标记不能反映权限失效 | 固定单应用/租户 OAuth v3 + S256、PG 摘要 state/code 消费、本人近期密码/MFA 显式绑定、bound_epoch 和最长七天核验；不保留平台 token | [接口依据与测试边界](25-飞书登录与显式绑定.md)。默认关闭，CLI 仅记录操作员证据，真实 POC-03 及全节点发布未验收 |

## 3. 协议能力与范围

OIDC/OAuth 授权码 + PKCE 是首期必需；SAML IdP 在 T2 作为独立验证包。Spring OAuth 授权服务器的官方定位是 OAuth/OIDC 基础，不能据此推断具备 SAML IdP。CAS、RADIUS 为后续接入选项，不直接加入当前 78 人天承诺。

项目文档中的 /oauth/* 为逻辑契约，框架实际端点需显式配置并通过发现文档公布；不得假设默认路径相同。JWT 即时撤销依赖资源服务集成状态校验，接入方拒绝集成时必须标记无法满足 A5，不能靠缩短 token TTL 宣称通过。
