# 应用软删除（N2 之"应用删除"部分）

> 本增量实现 T8 应用生命周期的**软删除**：应用可被删除，删除后**不可通过任何路径复活**，但保留注册数据与审计，不做物理删除。状态为**编码增量**，仅由远程 CI 验证；见 CI 绿灯前不标记完成。

## 1. 语义

- 删除是**不可逆**的：删除后 `oauth_client_status.deleted_at` 非空，应用从管理列表消失，且 `setEnabled`（启用/停用）一律返回 `409 Client deleted`，不能静默成功，也不能把删除当作一次"停用"来复活。
- 注册行 `oauth2_registered_client`、状态行 `oauth_client_status`、审计行 `auth_audit`、动作幂等行 `admin_client_action` 均**保留**，仅追加墓碑字段，不物理删除任何行。
- 删除同时把 `disabled=true`，因此入口过滤器 `ClientStatusFilter` 与公共客户端守卫、认证期围栏会像对待"停用"一样继续拒绝该客户端的协议端点；区别是删除状态优先于 `enabled`，且无法被 `setEnabled` 改写。
- 已删除的 `client_id` 注册行仍在：重复登记继续返回 `409`（不做复用）。需要复用编号时必须线下清理注册行后再登记；本文档明确此约定。

## 2. 状态机

| 状态 | `disabled` | `deleted_at` | 协议端点 | 管理列表 | `setEnabled` |
|---|---|---|---|---|---|
| 启用 | false | NULL | 放行 | 显示 | 可停用 |
| 停用 | true | NULL | 401 拦截 | 显示 | 可启用/再停用 |
| 删除（墓碑） | true | 非空 | 401 拦截 | **不显示** | **409 拒绝** |

状态只单向前进：启用 ⇄ 停用 之间可逆；任一口径进入"删除"后，状态机终点锁定，不再回到启用/停用。

## 3. 接口与幂等

- `POST /api/admin/console/clients/{clientId}/delete`，要求 `Idempotency-Key` 头（正则 `[a-zA-Z0-9_-]{16,128}`）、请求体 `{ "reason": "..." }`、应用管理员角色（`ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP`）+ 近期密码与 MFA。成功返回 `204`。
- 幂等键写入 `admin_client_action(action='DELETE')`，`ON CONFLICT DO NOTHING`：
  - **未用过该键（fresh）**：写入墓碑并审计一条 `CLIENT_DELETED`（含 `client_id` 与 `reason`，操作 `source_ip` 原样落库）。
  - **同一键重放**：同 reason 视为成功（不再重复审计/不再新增 action）；不同 reason 返回 `409 Idempotency context changed`。
  - **fresh 但该客户端已被别的键删除**（`deleted_at` 已非空）：返回 `409 Client deleted`，不重复删除。
- 删除在事务内：先 `accounts.lockAndRequire` + 复核应用管理员角色，再对 `oauth2_registered_client` 注册行 `FOR UPDATE` 加锁（与停用/轮换同一锁序），最后 `UPSERT oauth_client_status`（含 `deleted_at`/`deleted_by`/`delete_reason`），并 `UPDATE oauth2_authorization SET revoked=true WHERE registered_client_id = 注册记录 UUID`（不是 `clientId`），撤销真实授权族。

## 4. 审计

- 动作 `CLIENT_DELETED`，`detail` 仅含白名单键 `client_id` 与 `reason`（含 `operator` 由 `AdminAuditService` 自动附带），绝不写入任何密钥或签名。
- 管理端审计列表/导出仍可查到墓碑相关行；业务管理列表（`list()`）显式排除 `deleted_at` 非空的客户端。

## 5. 迁移

新增 `V17__client_soft_delete.sql`（**不修改 V14–V16**）：

```sql
ALTER TABLE oauth_client_status ADD COLUMN deleted_at timestamptz;
ALTER TABLE oauth_client_status ADD COLUMN deleted_by uuid REFERENCES iam_user(id);
ALTER TABLE oauth_client_status ADD COLUMN delete_reason varchar(500);
CREATE INDEX client_status_deleted ON oauth_client_status(deleted_at) WHERE deleted_at IS NOT NULL;
```

现有行默认 `NULL`（未删除），无需 backfill。

**回滚限制**：丢弃 V17 会丢失删除墓碑，已删除行会重新以"启用/停用"口径出现；且这些行虽仍 `disabled=true`，但 `deleted_at` 丢失后 `setEnabled` 将可再次把其改为启用——即回滚会破坏"不可复活"保证。因此 V17 属**单向迁移**，回滚需线下重建墓碑或确认不再需要不可复活语义。

## 7. 覆盖与未覆盖边界

- 服务层 `ClientAdminIT`：删除后列表排除、状态行墓碑、真实授权撤销、审计一条、同键同/异 reason 重放、新键再删 409、删除后 `setEnabled` 双向 409、无关客户端不受影响、未知 404 / 短键 400 / 空 reason 400 / 非管理员 403、注册行物理保留。
- HTTP `ClientManagementHttpIT`：SYSTEM_ADMIN 删除 204（控制器对 `ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP` 同一授权路径，服务层另有非管理员 403 用例）、列表消失、协议端点仍 401、`/state` 启用 409、同键重放 204、审计无密钥。
- 门户 `clients.test.ts`：必须精确 `clientId` 二次确认 + 原因，未满足不发请求；成功后列表移除；无密钥/存储泄漏。
- **未覆盖**：管理端审计查询里针对墓碑的"查看/导出"专项断言（仅复用既有审计列表能力）；多实例并发删除同一客户端的极端竞争（锁序已与停用/轮换一致，未单独起负向 IT）。
