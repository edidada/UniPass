## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T3。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 接口要求当前会话、近期认证及 Idempotency-Key，主体由服务端会话取得；新密码和确认值只在请求生命周期内存在。
2. PG 锁定用户控制行，创建 password_operation(PREPARED)，设置 password_gate=BLOCKED 并提升 auth_epoch 后提交。所有登录、签发、刷新和资源校验均检查 gate；阻断旧令牌后才允许目录写入。
3. 执行目录原生策略与改密。AD 用户改密使用 unicodePwd delete(old)+add(new)，管理员重置才使用 replace；OpenLDAP 使用已验证的密码修改能力。
4. 确认目录写成功后，同一 PG 事务更新 password_changed_at、operation=COMMITTED、写 sync_task/outbox/audit，再解除 gate。目录与 PG 之间不存在本地原子事务。
5. 目录明确拒绝：记录 REJECTED 并解 gate，epoch 不回退，用户重新登录。超时或进程崩溃：标 UNKNOWN 并维持 gate，返回 202 与 operation_id，禁止客户端自动重复写入。
6. 恢复任务扫描过期 PREPARED/UNKNOWN，根据目录可验证的版本变化及目标写入证据核对；证据不足转人工处置或受控重置，禁止凭超时推断失败。无需保存新密码。
7. 自助重置 token 只存摘要、10 分钟一次性有效，原子消费并绑定认证因素与用户；管理员重置需独立权限、MFA 和审计。统一走同一变更状态机。

## 3. 数据与契约

password_operation(id,user_id,idempotency_key,state,source_version,lease_until,error_code,created_at,finished_at)，唯一(user_id,idempotency_key)，不保存请求口令或口令摘要。iam_user 增加 auth_epoch bigint、password_gate。历史哈希由目录策略持有，取消 IAM 密码历史副本。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

在 gate 提交后、目录写后、PG 提交前和响应前分别杀进程；重复请求只返回同一 operation；同一秒连续改密 epoch 必须不同；任何 UNKNOWN 均不能放行旧令牌。

交付物：变更状态机实现、恢复任务、管理员恢复操作说明、故障注入报告；对应 A5、A6。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
