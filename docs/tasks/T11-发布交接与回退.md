## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T11。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 交付固定镜像摘要、配置模板、数据库迁移包、监控面板、告警路由、值班表和用户通知，不使用浮动 latest 发布。
2. 数据库采用 expand/contract：先加兼容字段和索引，再部署新代码，确认稳定后下版本清理旧字段；禁止直接回退破坏性 DDL。
3. 批次按 50 人 3 天、500 人 4 天、30% 5 天、全量推进；至少 12 个完整观察日，不将 3 人天执行工时当成 3 天自然周期。
4. 每批记录成功率分母、认证技术失败率、同步积压年龄、UNKNOWN 数、吊销时延和工单；任何安全绕过立即暂停扩大并启动处置。
5. 回退先停灰度和写入入口，恢复兼容应用版本；不恢复旧密码、不回退 auth_epoch、不重新激活已吊销令牌。目录已成功的改密必须保持有效。
6. 旧入口保留四周仅限受相同禁用和改密控制的兼容入口，不能绕过统一认证。交接需演示改密 UNKNOWN 恢复、死信重放、密钥轮换与备份恢复。

## 3. 数据与契约

发布记录含 commit、镜像摘要、迁移版本、配置变更、审批人、批次与回退结果；恢复凭证保管与审计分离。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

预生产演练应用回退、PG 时间点恢复、Redis 丢失与目录故障；恢复后验证禁用和 epoch 仍有效。

交付物：发布与回退记录、十二天灰度报告、SOP 交接签字、遗留问题责任表；对应 M5。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
