## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T10。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 建模凭证入口、签发、绑定、目录写入、管理权限及审计六个信任边界，记录攻击面与数据流。
2. 验证 OAuth/OIDC 的代码注入、PKCE 降级、重定向、nonce、JWT 算法与受众混淆、refresh 复用和登出通知重放。
3. 验证 LDAP 注入、对象越权、账号枚举、CSRF、限流绕过、日志泄密与密钥轮换；测试包含目录和飞书连接器故障路径。
4. 构建产出依赖清单与许可证清单，扫描依赖漏洞、镜像和 secret；结果绑定具体构建，禁止将旧扫描结论用于新镜像。
5. 缺陷记录攻击前提、复现证据、影响、修复 commit 与复测结果。高危必须清零，中危按验收放行规则处理。
6. 等保符合性逐条映射技术控制、制度与外部测评证据；设计目标不等于已经通过等保测评。

## 3. 数据与契约

安全报告仅保存脱敏重现请求、角色与证据路径，不保存活跃 token；访问按安全审查角色限制。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

每条缺陷关闭需原复现失败且正常流程通过；轮换后旧密钥在约定窗口外不能验证新请求。

交付物：威胁模型、漏洞整改报告、依赖清单和合规差距表；支撑 M4 放行。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
