## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T4。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 首期采用 AD 作为密码权威源；域内 Windows 使用原生 Kerberos，不由 IAM 替代 Winlogon。
2. 记录域、DNS、时间同步、域控站点与复制拓扑；IAM 最小权限账号可在指定 OU 执行必要操作，不使用 Domain Admin。
3. 联合登录方向先做 PoC：AD FS 为 IdP 时 IAM 是 RP；IAM 为 IdP 时下游必须明确支持的信赖关系。冻结 metadata、entityID、ACS、签名证书及声明映射后再下发。
4. 组策略先发测试 OU，再按部门扩大；保存原策略备份及撤销步骤。OpenLDAP 不等于 Windows 域控，无 AD 的桌面替代方案独立评审。
5. 离线缓存登录、已签发 Kerberos 票据与现有 Windows 会话不受 IAM JWT 吊销控制；如需即时锁屏或票据治理，建立独立终端管理任务。

## 3. 数据与契约

产出域与信赖配置清单、employee_no 声明映射、证书轮换清单；目录服务账号凭证进入密钥系统。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

在线新登录新密码通过、旧密码失败；复制延迟和域控离线分别测试。缓存登录与现有票据单独记录，不宣称全端即时失效。

交付物：测试 OU 策略包、域登录证据、联合 PoC 报告、回退脚本；对应 A2、A5-7。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
