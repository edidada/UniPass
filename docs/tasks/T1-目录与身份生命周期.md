## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T1。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. 建立 DirectoryGateway：findByStableId、verifyCredential、changePassword、disableUser；区分只读绑定与写目录身份，禁止匿名访问。
2. HR 导入先落 staging，校验 employee_no 非空且唯一，记录 batch_id、源版本和校验摘要；预览差异经确认后提交，异常行隔离，不影响有效行。
3. 以目录 objectGUID/entryUUID 保存稳定锚点，DN 仅作为可变定位字段；员工号变更走人工核对，禁止按邮箱自动合并。
4. 全量初始化后按源游标增量拉取；游标与已应用批次同事务保存。离职先禁用并增加 auth_epoch，再清会话；删除延后至保留期结束。
5. 写目录只发往已确认可写节点；读副本复制延迟不可用来证明改密成功。禁止通过提升只读副本自动恢复写入。

## 3. 数据与契约

iam_user 增加 directory_id、directory_type、source_version、directory_etl_at；directory_id 与 employee_no 分别唯一。导入记录保存批次、行号、错误类型及重跑状态。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

重复员工号、DN 迁移、分页中断重跑、离职与登录并发、目录证书过期、主副本延迟；证明重跑不会新增重复身份。

交付物：目录初始化脚本、字段映射表、导入差异报告、LDAPS 连通证据；对应 A2、A7。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
