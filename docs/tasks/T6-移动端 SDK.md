## 1. 目标与边界

承接 [PM 任务规划](../05-PM开发子任务规划与里程碑.md) 的 T6。公共技术决策见 [技术选型](../08-技术选型与决策记录.md)，跨文档口径见 [设计基线](../09-设计基线与待确认事项.md)。本文的完成标准必须以交付证据验证，不能以文档完成代替实现完成。

## 2. 处理流程与实现约束

1. login 创建 state、nonce 和 verifier，使用系统浏览器授权；每次授权上下文独立保存，回调核对 state、issuer 及绑定的回调地址。
2. 原生公共客户端仅走授权码 + PKCE，不持有 client_secret，不通过 /api/authn 直接换 token。
3. 登录态机为 SIGNED_OUT → AUTHORIZING → SIGNED_IN → REFRESHING；invalid_grant 或 TOKEN_REVOKED 清理并进入 SIGNED_OUT，网络错误保留安全存储并提示重试。
4. iOS Keychain、Android 系统 Keystore 支持的安全存储封装 refresh token；access token 优先内存保存。设备迁移和备份恢复不能迁移会话凭证。
5. 同一设备刷新使用 single-flight；登出先请求服务器撤销再清本地，离线登出清本地并记录无法确认远端撤销。
6. 推送只触发清理，不作为唯一安全控制；应用每次 API 请求依赖服务端 epoch 校验。生物识别仅用于解锁本地凭证，不等于首次认证。

## 3. 数据与契约

SDK 配置 issuer、client_id、redirect_uri、scope；暴露 login、getValidAccessToken、logout、clearTokens 和结构化错误，禁止输出 token 日志。

字段与接口以 [公共详细设计](../04-详细设计文档.md) 为起点；新增表和字段必须配数据库迁移及回退兼容说明。内部 ID 采用不可变 UUID，时间统一 UTC，日志回传 trace_id；业务错误使用公共错误信封，协议错误遵循对应协议。

## 4. 异常处理与运维

依赖调用设置连接与总超时，不无限重试；写入结果不明时保留 operation_id 与可恢复状态。关键指标按任务、结果和依赖统计，禁止以用户 ID 作为高基数指标标签。认证、授权和状态校验故障均拒绝放行；管理员操作和人工修复必须留审计。

## 5. 验证与完成标准

iOS/Android 真机各覆盖回调劫持、取消授权、进程重启、刷新并发、系统时间偏差、推送丢失、改密后 API 拒绝。

交付物：双平台 SDK、示例 App、接入说明、真机报告；对应 A4、A5-6。

开发自测、QA 验证和责任人评审分别记录 commit、执行时间、环境与证据位置；未执行填“未执行”，不得预填通过。
