# 设计基线与待确认事项

版本 V1.0，2026-10-18。本文为现有七份方案的补充修订基线；存在冲突时，以本基线和 tasks 下对应任务设计为准。现有命令、DDL 和配置均为设计示例，尚非可直接执行的部署交付。

## 2. 公共数据迁移增量

以下为实施要求，不是已验证的可运行 SQL。T2/T3/T5 必须提供完整建表、外键、索引、检查约束、升级与兼容迁移脚本。

- iam_user：auth_epoch bigint 非空默认 0、password_gate 枚举 OPEN/BLOCKED、directory_id 唯一；密码相关控制字段仅认证领域服务可改。
- password_operation：操作 ID、用户、幂等键、PREPARED/COMMITTED/REJECTED/UNKNOWN 状态、目录源版本、租约、错误类型及时间；每用户只允许一个未完成改密，使用部分唯一索引或锁定用户行强制执行。
- refresh_token_family / refresh_token：族状态、父子关系、令牌摘要、使用时间、过期时间与 epoch；轮换和重放检测必须事务化。
- outbox_event：事件 ID、schema_version、聚合用户、auth_epoch、类型、无口令 payload、创建/领取/投递时间；event_id 唯一。
- sync_task：唯一(event_id,target)，增加租约版本、租约截止与下次重试时间；终态包括 SUCCESS、已证实的 SUCCESS_DEGRADED、SKIPPED、DEAD；权限阻塞用 BLOCKED。
- reset_token：摘要唯一、用户、认证因素、过期与消费时间，禁止保存原始 token。

状态查询 GET /api/password/operations/{id} 仅允许本人或获授权管理员；返回操作状态、是否需要人工恢复与 trace_id，不返回目录敏感属性。202 表示处理中，409 表示已有冲突操作，成功仅在目录结果与 PG 最终提交都可确认时返回。

## 3. 验收修订

A5-8 的“全端即时旧密码不可用”限定为 UniPass 在线认证及可控 AD 在线新登录。离线 Windows、已有 Kerberos 票据、飞书独立账号凭证不在此保证内。若业务要求覆盖，需新增需求、方案和预算，不能以当前设计签收。

A5-5 区分“UniPass 应用内重新认证”与“飞书全局会话撤销”，按能力矩阵验收；不得以外部静默免登绕过改密后的近期认证。A5-6 推送是体验控制，服务端五秒内拒绝旧 token 是安全标准。尾延迟报告遵循 T9 的样本与窗口要求。

安全指标均为设计目标而非测评结论；备份恢复、主从切换与 fail-closed 行为必须经故障演练取证。

## 4. 排期修订

原 WBS 合计 78 人天不含本次新增恢复流程、PoC 与独立 SAML IdP 验证的重新估算。PM 应在 PoC 后重估，不直接将细化文档当成既有工时内承诺。

原关键路径 T1→T2→T9→T10→T11 未计入接入支线等待，不能作为严格关键路径：T9 必须等待 T3–T8 全部完成，再结合角色资源重新计算。G1/G2/G3 共十二个观察日，T11 的三人天仅为操作投入；M5 日期需按实际工作日与观察窗口重排。M5 指全量切换，旧入口在全量四周后满足条件才关闭。
