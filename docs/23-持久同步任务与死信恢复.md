# 持久同步任务与死信恢复

2026-10-21，T5 基础设施增量。V10 接续已有密码事务 outbox，加入禁用事件、原子 fan-out、短租约 worker、有限重试、队列报告与离线死信恢复。飞书免登、租户能力验证、飞书/推送适配器、事件回调及外部最终状态对账仍待实现，不将本增量作为 T5 整体验收。

## 事件与任务事务

已有密码变更/核验恢复成功以 operation UUID 作为 event_id，类型 `unipass.password.changed`；只有本地提交确认后产生事件。新增 `unipass.user.disabled`：身份从非 DISABLED 变为 DISABLED 时，由数据库触发器同事务生成事件。离职导入和单独禁用共用此边界；重复写入 DISABLED 不重复发事件，后续重新启用再禁用产生新的事件。

V10 对以上两种事件插入固定的 `FEISHU_APP_REAUTH`、`APP_PUSH` 任务，唯一 `(event_id,target)`；旧密码生产者继续显式插入也不会生成重复任务。`published_at` 仅表示两个任务已持久化，不能解释为下游投递成功。任一插入或审计失败使对应事务回滚，不在内存队列与数据库之间留下双写间隙。

升级保留已有任务 ID、结果与尝试次数，补齐缺少的 fan-out；旧 RUNNING 转回 PENDING 并清理旧租约。对当前已禁用、尚无同 epoch 禁用事件的身份补发任务。独立身份 CLI 仅携带 V1；共享数据库必须先由服务升级/迁移至 V10，才能取得此处新增触发器保障。迁移账号与运行账号权限分离、历史数据规模与备份回退仍需部署验证。

`SyncTaskDelivery.Event` 只暴露 event_id、用户 UUID、类型、auth_epoch、事件时间，不把 outbox 任意 JSON、口令、令牌或远端错误正文交给适配器。密码生产者沿用无口令 payload；禁用 payload 只有 user_id/auth_epoch。schema_version 非 1 或不支持的类型在调用适配器前进入 DEAD。

## 领取、调用与确认

每次处理一个到期 PENDING 或租约过期 RUNNING，数据库 `FOR UPDATE SKIP LOCKED` 领取；尝试次数、随机 lease_token、worker UUID、单调 lease_version 和 30 秒租约同事务提交，并记录 CLAIMED 审计。外部调用期间不持有领取事务的行锁。

生产调用总等待上限 5 秒，超时/异常统一记录 OUTCOME_UNKNOWN，不保存异常消息。取消不能证明外部未执行：适配器必须透传 event_id 幂等键，或在重试前核对外部结果。只有外部确认结果可返回 SUCCESS；SUCCESS_DEGRADED 的预留含义为已实证本地访问撤销，当前没有适配器返回该结果。未注册目标立即 BLOCKED/CAPABILITY_MISSING，权限拒绝使用 BLOCKED/PERMISSION_DENIED，均不会当作成功。

执行池每实例最多两个 daemon 调用线程，没有等待队列。忽略中断的适配器会占用容量；后续请求记录 LOCAL_CAPACITY 并重试，不无限创建线程。实际 HTTP 适配器还必须设置自身连接、响应体和总超时；引擎超时不能代替网络客户端释放资源。

确认在另一个短事务中检查 RUNNING、owner、token、version 与未过期租约，再原子写结果和 FINISHED 审计。租约过期或新 worker 已接管时，迟到结果不能覆盖新结果。进程在外部成功之后、确认之前退出会发生再次投递；保证至少一次，不保证外部恰好一次。

## 重试、告警与人工恢复

首次调用加最多三次自动重试，总计四次。延迟依次为 1/5/15 分钟，加 0–10 秒抖动。适配器提供的 Retry-After 等待时长为下限；当前 SPI 接受 0–7 天，实际适配器遇到更长时长应阻塞并要求人工处置，不能截短后提前调用。时间以 PG 为准，重试截止与更新时间使用同一语句时间。最后一次 RUNNING 崩溃后，租约超时直接 DEAD/LEASE_EXPIRED，不进行第五次调用。

BLOCKED/DEAD 写数据库且记录不含用户 ID 的告警日志。企业告警接入、队列容量、全节点故障和定时外部对账尚未验证；本地 report 是队列盘点，不能证明外部最终状态。

使用服务可执行包运行操作员 CLI，无需启动 LDAP、Redis、HTTP 或密钥服务：

```powershell
java '-Dloader.main=com.unipass.server.SyncTaskAdminCli' -cp iam-server/target/iam-server-0.1.0-SNAPSHOT-exec.jar org.springframework.boot.loader.launch.PropertiesLauncher report
java '-Dloader.main=com.unipass.server.SyncTaskAdminCli' -cp iam-server/target/iam-server-0.1.0-SNAPSHOT-exec.jar org.springframework.boot.loader.launch.PropertiesLauncher tasks
java '-Dloader.main=com.unipass.server.SyncTaskAdminCli' -cp iam-server/target/iam-server-0.1.0-SNAPSHOT-exec.jar org.springframework.boot.loader.launch.PropertiesLauncher retry <任务UUID>
```

统一从受保护环境读取 `UNIPASS_DB_URL/USER/PASSWORD`。report 输出 target/state 数量与最早更新时间、未路由事件数和缺少目标任务数；多条查询为运行中盘点，不作为全局一致外部验收快照。tasks 最多输出 100 条 BLOCKED/DEAD 的任务及事件 ID、尝试次数、版本和固定错误码，不输出 payload 或用户信息。

retry 还要求 `UNIPASS_OPERATOR_REF` 与 `UNIPASS_EVIDENCE_REF`，格式与 MFA key CLI 一致。仅允许 BLOCKED/DEAD，重置尝试数、增加版本、重新到期；原次数、操作员和证据引用同事务保留在 REQUEUED 审计。其他状态返回 changed=false，未知任务失败。人工先修复能力或权限并核验未知结果；重排不会使缺失适配器变为可用。离线 DB 操作员边界不自动验证工单真实性；Web RBAC 管理与不可改归档属于 T8。

调度沿用 `unipass.jobs.enabled`，新增 `unipass.jobs.sync-delay-ms`，默认 1000ms，每次一项。统一构建入口运行 `SyncTaskDeliveryIT` 的真实 PG 故障用例与实际服务包 CLI；最终 Maven/Gradle 验证结果在完成后记录。
