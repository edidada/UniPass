# 停用/删除的后端退出任务围栏

> 本增量在停用或软删除应用时，把该客户端尚未投递的 `oidc_logout_task` 标记 `DEAD`，避免撤销授权触发的新任务继续调用已被停用/删除的 RP。状态为**编码增量**，仅由远程 CI 验证。

## 1. 语义

- 停用/删除在**同一事务**内先撤销该客户端的授权族（按注册记录 UUID），V8 触发器会为每个新撤销的授权入队 `PENDING` 退出任务；随后立即执行：
  ```sql
  UPDATE oidc_logout_task SET state='DEAD', finished_at=?
  WHERE client_id=? AND state IN ('PENDING','RUNNING')
  ```
- 因此：刚入队的任务与更早的 `PENDING/RUNNING` 任务都不会再被 worker 选中投递；`SENT/DEAD` 不受影响。
- **重新启用不会复活**被围栏的任务；已撤销的授权也不会复活。
- 停止的是"新的投递"：另一个 worker 中已进入 HTTP 调用的 `RUNNING` 任务可能仍完成一次请求；本保证是提交后不再投递。若要严格取消在途请求，需要 worker 侧协作取消，未做。

## 2. 与 V8 触发器的关系

- V8 的 `authorization_backchannel` 触发器只在 `revoked` 从 false→true 时入队；本增量不修改触发器。
- 围栏发生在撤销之后、同一事务内，因此看到的是刚入队的行；若触发器未入队（没有 `oidc_rp_session`），围栏仍会清理该客户端已有的未完成任务。
- 未新增迁移；复用 V8 表与索引。

## 3. 测试

`ClientAdminIT.disableAndDeleteFenceLogoutTasksWithoutTouchingOtherClients`（真实嵌入式 PostgreSQL）：
- 为 crm 造授权 + RP 会话（触发 V8 入队）以及一个既有 `PENDING` 任务；
- 停用 crm 后：crm 的触发任务 + 既有任务均 `DEAD` 且 `finished_at` 非空；0 个 `PENDING/RUNNING`；另一客户端 hrm 的任务保持 `PENDING`；
- 重新启用 crm：任务仍 `DEAD`；
- 删除 hrm：hrm 的 `PENDING` 任务变 `DEAD`，0 个未完成。
- 既有停用/删除 HTTP 测试继续覆盖协议端点 401 与列表隐藏。

## 4. 边界与未做

- 在途 `RUNNING` 请求不被强制中断；worker 可能完成一次已发出的调用。
- 停用/删除不清理 `oidc_rp_session` 行（审计/排障保留），只围栏任务。
- 多实例 worker 的租约/选举仍见 docs/32 N3；本增量只保证被围栏行不会再被领取。
