# 应用管理与客户端密钥轮换

版本 V1.0（2026-10-24）。T8 第二期编码增量，承接 [管理控制台与审计查询](27-管理控制台与审计查询.md)。不改变 T8 或全项目验收状态。

## 范围

V14 迁移与管理控制台应用管理：

- `AdminClientService/Controller`（`/api/admin/console/clients`）：列出已登记应用、登记新应用、轮换机密客户端密钥。权限为 `ROLE_SYSTEM_ADMIN` 或新增 `ROLE_ADMIN_APP`（对应 T8 的 APP_ADMIN 概念，可通过角色管理或离线 CLI 授予）。
- 登记沿用 `ClientRegistrationService` 的既有校验（客户端 ID `[A-Za-z0-9_.-]{3,100}`、HTTPS/精确回调、最多 10 个回调、必须含 openid、后端退出地址固定路径与同源）。机密客户端由服务端生成 43 字符 url-safe 密钥，响应中仅出现一次；数据库只存 delegating password encoder 哈希。
- 轮换：新密钥写入当前 client 行，旧哈希写入 `oauth_client_secret_previous` 并保留至 `unipass.clients.secret-rotation-window`（ISO-8601，默认 `PT24H`，允许 1 分钟–7 天）。`PreviousClientSecretAuthenticationProvider` 在内置 `ClientSecretAuthenticationProvider` 之后作为回退参与客户端认证，仅在窗口内、且仅接受已登记的历史哈希；过期条目读取时忽略。每个客户端只保留一个前序密钥，重复轮换会覆盖上一个前序窗口。
- 幂等：轮换要求 `Idempotency-Key`（`[a-zA-Z0-9_-]{16,128}`），同键第二次请求返回 409，避免一次重试签发两个密钥；`admin_client_action` 记录 actor/client/action/key/原因。
- 审计：`CLIENT_REGISTERED`、`CLIENT_SECRET_ROTATED` 与业务变更同事务提交；detail 仅含 `client_id`、`kind`、`previous_secret_valid_until`、`operator` 等白名单键，从不包含密钥或完整请求体。
- 门户新增 `/portal/admin/clients`：应用列表、登记表单与一次性密钥展示（关闭/刷新后不可再读）、逐应用轮换入口；导航按 `ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP` 出现，服务端每次请求复查角色。

## 边界与未完成

- 前端未提供应用详情编辑（回调增删、scope 调整）、停用/删除、客户端状态与密钥有效期设置；这些仍属 T8 后续。
- 目前只有"当前 + 一个前序"两把密钥；同时保留多代前序、按客户端配置窗口、企业 KMS/HSM 托管与泄露后立即清空窗口未实现。
- 客户端登记仍要求至少一个回调；纯客户端凭证模式（client_credentials）未开放。
- `ROLE_ADMIN_APP` 与 `ROLE_SYSTEM_ADMIN` 未做字段级最小权限拆分（例如只读审计员 AUDITOR 仍缺）。
- 测试不代表真实 RP 联调；滚动发布、跨实例缓存与生产密钥托管仍需外部证据。

## 运维顺序

1. 先发布含 V14 迁移与回退认证器的版本（旧密鈅继续可用）。
2. 在控制台轮换密钥，先更新 RP 配置再确认旧密钥自然过期；窗口内不重复轮换同一客户端。
3. 回退：应用仍可使用旧密钥直至窗口结束；`oauth_client_secret_previous` 可由 DBA 删除以立即失效（需审计）。
4. 首次应用管理权限：`AdminRoleCli grant <employee_no> ROLE_ADMIN_APP` 或由 SYSTEM_ADMIN 在 `/portal/admin` 授予。
