# 第二阶段：密码核心与恢复

本文记录 T3 的可复用领域实现，不代表 T2 的 HTTP/OIDC、MFA 或 T3 全链路验收已完成。所有阶段仍按 [阶段进度](10-阶段实施进度.md) 推进。

## 1. 模块与入口

新增 `iam-password`，依赖第一阶段的目录接口和 PG 数据访问。V2 迁移保留 V1 的校验和，新增改密操作、请求节流、验证凭据、重置凭据、审计、outbox 与同步任务表。

| 领域入口 | 用途 | 调用边界 |
|---|---|---|
| PasswordChangeService.change | 用户凭旧密码改密 | AuthenticatedActor 必须由认证服务构造；五分钟内认证、当前账号版本 |
| PasswordChangeService.reset | 使用一次性重置 token | token 绑定用户与 auth_epoch，10 分钟有效；只保存 SHA-256 摘要 |
| PasswordChangeService.adminReset | 特权管理员重置 | PASSWORD_RESET 权限、近期 MFA、管理员账号有效；成功后强制用户下次改密 |
| PasswordChangeService.get | 本人查询操作状态 | 服务端绑定请求用户，不从请求体采信 actor/user_id |
| PasswordChangeService.markAbandonedUnknown | 扫描过期操作意图 | 仅改状态与记审计，不重放目录写入 |
| PasswordChangeService.recover | 人工证据恢复 | PASSWORD_RECOVERY 权限、近期 MFA、过期租约及证据引用；决策与审计同事务 |
| ResetGrantService.issueFromVerification | 换取一次性重置 token | 只消费可信因素适配器已持久化的 identity_verification；不能把前端自行声明当验证结果 |

这些入口目前是 Java 领域接口，**尚未暴露 HTTP 端点**。后续 IAM 服务须先完成认证、CSRF、MFA、权限与对象归属验证，再调用领域接口；不得将 AuthenticatedActor 直接绑定为 JSON 请求参数。

## 2. 改密顺序与失败语义

1. 校验幂等键、近期认证和目录历史策略验证开关；重复请求返回原操作，不重写目录。
2. 行锁校验账号和 epoch，持久化每分钟一次的请求节流；验证本地密码策略与旧凭证。
3. 再次校验账号状态和版本，创建 PREPARED，递增 auth_epoch 并设置 BLOCKED，然后提交 PG。目录调用不持 PG 行锁。
4. 目录明确成功后，以 PG 事务写 COMMITTED、密码时间、审计、无口令事件及每目标任务，再按相同 epoch 和 ACTIVE 状态解除 gate。
5. 目录明确拒绝才置 REJECTED 并解除当前 gate，epoch 不回退；超时或结果不明置 UNKNOWN 并保持阻断。
6. 目录成功而 PG 最终事务失败时，不产生部分事件；操作仍保持阻断，并转 UNKNOWN。若连记录 UNKNOWN 也失败，抛出带 operation_id 的 STORAGE_UNAVAILABLE；原 PREPARED 之后由扫描任务发现。

目录凭证版本仅作为核对线索；发生变化不证明本次写入成功，不能据此自动开 gate。重复查询和重复请求也不会自动完成未知写入。

并发离职会提高自己的 epoch 并保持 DISABLED/BLOCKED；即使改密随后返回成功，也不会重新激活该账号。管理员重置成功后保留 must_change_password，普通用户完成后续改密才清除。

## 3. 密码与目录边界

输入 char[] 在服务返回或异常时清空；Unicode 校验和 LDAP 库可能创建短生命周期字符串，不宣称 JVM 内口令始终可完全擦除。数据库、审计、操作记录、事件与任务均不保存新旧口令或口令哈希。

本地规则包含 Unicode 码点长度、三类字符、控制字符、常见弱口令、姓名/员工号、连续或重复字符；生产弱口令词库和按组策略配置仍需后续配置管理。历史不可复用由目录执行，不在 IAM 复制哈希。

用户改密和特权重置分别有 `directoryHistoryVerified`、`resetHistoryVerified` 开关，默认构造不启用重置策略验证。真实 AD/OpenLDAP 的策略、ACL 与管理员重置是否绕过历史检查必须分别取证，不能因用户改密测试通过而默认管理员重置也安全。

AD reset 使用 writer 的 unicodePwd replace，用户 change 仍使用用户绑定下的 delete/add；OpenLDAP 采用标准扩展操作。两类写入都要求已确认可写节点，使用 LDAPS；账号稳定锚点检查防止将 DN 复用误认作原用户。

## 4. 验证与限制

```powershell
mvn -pl iam-password -am verify -Pintegration -B -ntp
```

新增 PasswordPolicyTest 和 PasswordChangeIT，使用真实 PostgreSQL 17.6 验证事务，目录写入由可注入失败的测试实现控制。测试覆盖写前阻断、目录拒绝、目录写前/写后超时、PG 最终提交失败、四个中断边界、离职竞争、幂等、并发、授权恢复、重置 token 的摘要/过期/版本绑定及管理员强制改密。

中断测试通过抛出不可恢复 Error 模拟服务流程中止，并验证连接关闭后的事务状态；尚未执行真实进程 kill、网络丢包或生产 LDAP 故障注入，这些仍属于 T9 交付。OIDC JWT 的跨应用五秒吊销必须等 T2 资源服务和会话实现后端到端验证。

2026-10-18 19:29（Asia/Shanghai）完整回归通过：LDAPS 7 项、CSV 2 项、身份导入集成 13 项、密码策略 2 项、密码事务集成 19 项，共 43 项，失败、错误和跳过均为 0；命令 `mvn verify -Pintegration -B -ntp`，约 47.4 秒。此结果仅覆盖当前目录与密码领域代码。

## 5. 打包调整

`iam-identity` 保留普通库 JAR 供后续模块引用，操作员可执行包改为 `iam-identity-0.1.0-SNAPSHOT-cli.jar`。第一阶段运行说明和打包测试已同步。第二阶段服务运行时必须同时加载 V1、V2 迁移；单独第一阶段 CLI 只包含 V1，不作为后续整体数据库的升级入口。
