# 应用生命周期与只读审计员

版本 V1.0（2026-10-24）。T8 第三期编码增量，承接 [应用管理与客户端密钥轮换](28-应用管理与客户端密钥轮换.md)。

## 范围

- **应用编辑** `PUT /api/admin/console/clients/{clientId}`：替换显示名称、回调/退出回调、scope 与后端退出地址，沿用登记时的严格校验（HTTPS、精确匹配、最多 10 条、必须含 openid、同源固定退出路径）。客户端 ID 与类型不可变；当前密钥保留。编辑与 `CLIENT_UPDATED` 审计同事务。
- **停用/启用** `POST /api/admin/console/clients/{clientId}/state`：启用状态存 `oauth_client_status`。停用时在同一事务内把该客户端所有未撤销的 `oauth2_authorization` 置为 revoked（V8 触发器因此生成后端退出任务）。新过滤器 `ClientStatusFilter` 在授权服务器过滤器之前拦截 `/oauth/authorize`、`/oauth/token`、`/oauth/introspect`、`/oauth/revoke` 的停用客户端（401 `invalid_client`），因此不依赖 provider 顺序，也不受缓存或签名窗口影响。启用只恢复协议入口，不复活已撤销的授权。
- **幂等**：状态变更要求 `Idempotency-Key`；同键同上下文重放返回成功但不重复审计、不重新应用状态（不会意外复活后续停用）。同键不同原因返回 409。
- **只读审计员**：新增 `ROLE_ADMIN_AUDIT`，仅可调用 `/api/admin/console/audit`、`/audit/export`；角色管理仍需 `ROLE_SYSTEM_ADMIN`，应用管理需要 `ROLE_SYSTEM_ADMIN` 或 `ROLE_ADMIN_APP`。审计员在门户只看到审计卡片，不渲染角色表单。
- 门户 `/portal/admin/clients` 增加状态徽标、停用/启用（含原因与二次确认）与就地编辑表单；`/portal/admin` 对审计员展示审计列表。

## 边界与未完成

- 应用删除、回调历史、密钥有效期/停用后立即清除前序窗口、按客户端自定义轮换窗口未实现。
- 停用只撤销授权族，不主动清理 RP 本地会话以外的其他缓存；五秒端到端时延与多实例证据仍待外部验证。
- `ROLE_ADMIN_AUDIT` 只能读 JSON/CSV，无字段级脱敏配置；审计归档、六个月恢复与真实 LB 来源 IP 仍未实现。
- 编辑表单允许调整 scope，但未实现"缩小 scope 后重新征得同意"的交互（当前服务为 requireAuthorizationConsent=false）。

## 运维要点

1. 发布顺序：先升级 schema（V15）与服务，再在控制台停用或编辑应用；旧版本节点无 `oauth_client_status` 过滤，滚动期间应避免通过新版本停用后仍路由到旧节点。
2. 停用会撤销授权并触发后端退出；确认 RP 已实现通知接收后再停用生产应用。
3. 回退：V15 表可保留，旧版本忽略；重新启用需有 `ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP` 与近期密码+MFA。
