# 登录会话管理与独立吊销

版本 V1.0，2026-10-21。对应 T2/T7 的登录列表与单次登录吊销后端；Vue/TypeScript 门户、真实浏览器和跨主机验收仍未完成。

## 技术选项与决策

| 选项 | 行为与代价 | 决策 |
|---|---|---|
| 删除 Redis 会话 | 能删除已知 Cookie 对应记录，不能同时吊销已签发的 JWT/refresh；SID 在 MFA/再认证时会轮换 | 不作为吊销依据 |
| 每次吊销递增用户 epoch | 复用全局退出，但其他设备也失去访问 | 保留给全局退出、身份/密码变更 |
| PostgreSQL 持久登录 ID + 授权族映射 | 增加登录状态查询和两个表；可与既有身份锁、授权事务和 V8 通知队列一起提交 | 本次采用 |

Spring Session 提供按 principal 查询和删除会话的接口，但目录权限与令牌生命周期仍需应用约束。这里以 PG 登录记录作为门户管理对象，Redis 继续承担 Cookie 会话。依据：[Spring Session API](https://docs.spring.io/spring-session/reference/api.html)。共享身份行的锁一直持有到事务结束，同行上的更新/锁请求会等待；据此让签发与吊销形成顺序是本项目的设计判断，依据：[PostgreSQL 17 行锁](https://www.postgresql.org/docs/17/explicit-locking.html#LOCKING-ROWS)。没有新增运行依赖。

## 数据与迁移

V12 新增：

- `iam_login`：随机 UUID、归属用户、epoch、原始认证时间、最近浏览器活动、认证来源、粗粒度设备、吊销时间。
- `iam_login_grant`：授权族 ID 到登录 ID 的映射，覆盖所有客户端，包含未登记 backchannel 的客户端。
- `auth_audit.login_id`：吊销目标 ID，与审计同事务；不存 Cookie、口令、OTP、IP 或原始 User-Agent。

登录 ID 是管理标识，不能用于登录、换 token 或恢复密码。密码与飞书登录在认证事务内登记；两次相同用户/epoch/认证时间的登录仍使用不同随机 ID。`withMfa`、密码再认证、JSON/JDK 会话恢复保留原 ID，轮换 servlet SID 不新建登录。

旧 JSON/JDK 会话没有此 ID，反序列化不随机补造 ID。V12 对 ACTIVE/OPEN 身份递增 epoch，并撤销所有旧授权族，通过 V8 触发器入队已有 RP 通知。BLOCKED 身份的 epoch 与 UNKNOWN/PREPARED 改密恢复围栏保持原值。升级会要求重新登录及按原规则续绑飞书；已有邮件恢复授权也受新 epoch 约束。迁移必须停旧节点，备份后执行，完成后以全量新节点启动；不能让不检查 login ID 的旧节点继续处理请求。回退应用前先维护模式并撤销新授权/清理 Redis 会话，数据库前滚修复优先，不能在线删除 V12 表或还原旧 epoch。

## 接口与展示语义

契约见 [OpenAPI](openapi.json)，增加两个路径，总路径数 31。

| 接口 | 契约 |
|---|---|
| `GET /api/session/logins?before=<UUID>` | 当前用户、当前 epoch、未吊销的登录记录；按原始认证时间和 ID 倒序；每页 50，`nextCursor` 为空表示结束 |
| `POST /api/session/logins/{id}/revoke` | 必须有 CSRF、单个精确 IAM issuer Origin、五分钟内真实口令证据及需要时的近期 MFA；成功 204；外人或不存在的 ID 均 404 |

返回 `id/authenticatedAt/lastAccessAt/method/device/current`，不返回 Redis session ID、Cookie 或任何 token。游标也是本人登录 ID，外人游标返回 404。`current` 可能出现在后续页面，前端必须支持分页。

设备字段仅从最多 1024 字符的头推导浏览器/系统类别，不存版本与原始头；头可被伪造，不能作为认证证据。活动时间最多每分钟更新一次，不等于精确心跳。列表是持久登录和授权的管理视图，不保证对应的 Redis Cookie 仍存在；RP refresh 可能比浏览器会话长寿。故不按 Cookie 的 8 小时空闲/24 小时绝对上限隐藏仍可吊销的登录记录。浏览器的原限制继续由 Redis 与 SessionEpochFilter 执行，令牌按自身期限和实时登录/授权族状态校验。

## 吊销事务与竞态

1. 锁当前身份行，检查状态/gate/epoch/Redis generation、登录未吊销与飞书当前绑定（如适用）。
2. 校验真实密码/MFA、目标用户/epoch；设置目标 `revoked_at`。
3. 将目标映射的全部授权族设为 revoked，V8 触发器同事务入队已登记的 RP 通知。
4. 写包含目标登录 ID 的审计，提交成功后返回 204。其他登录的 epoch 与授权保持不变。

重复目标在调用者仍有效时幂等；本人吊销当前登录会使当前 Cookie 会话失效，后续请求必须重新认证。其他设备不依赖即时 Redis 删除：其请求逐次检查 PG 登录状态，旧 Redis 内容恢复、SID 轮换、重新发送旧 Cookie 均不能绕过吊销。

授权保存与 refresh 同样先锁身份行并检查登录，已有授权不允许换绑到其他登录。因此刷新先提交时，它的新 token 也被后续吊销；吊销先提交时，刷新不能保存。JWT 增加 `unipass_login` 并检查归属/epoch/吊销状态；内省与换码检查保存的 principal 登录。MFA、因素生命周期、显式绑定、密码再认证和全局退出的敏感事务也复查 principal，避免只在过滤器检查一次。

`iam-password` 不依赖 server 表，新增事务内 `CredentialGuard` 接口与 actor 的 login ID；IAM `CoreConfiguration` 必须注入严格 PG 检查，在锁身份后、目录校验前和 prepare 前复查。目录校验期间被吊销时，不写新密码、不建立 password operation。独立领域测试/离线调用保留原受信 actor 构造方式，不能将该路径暴露成未接 IAM guard 的 Web 接口。

数据库或状态检查异常拒绝请求；提交未确认不会返回成功，登录、授权、通知与审计同事务提交或回滚。已确认的数据库提交失败会回滚；提交通信中断可能结果未知，503 不等于未执行。若响应丢失或提交结果未知，可在另一个仍有效登录中查询列表、重复同一目标；不需要重发密码或重建授权。已在吊销前完成授权检查的只读请求可能完成；此变更不声称取消任意在途业务工作。
