# 客户端回调地址历史（N2 之"回调历史"部分）

> 本增量实现 T8 应用管理的**回调配置历史**：每次登记与每次真实回调变更都被追加式留痕，供审计与回溯。状态为**编码增量**，仅由远程 CI 验证；见 CI 绿灯前不标记完成。

## 1. 语义

- 历史是**追加式（append-only）**快照：每次 `register` 写一条 `REGISTER`，每次**真实回调变更**的 `update` 写一条 `UPDATE`；不更新、不删除历史行。
- 只记录**真实回调变化**：比较 `redirect_uris`、`post_logout_redirect_uris`、`backchannel_logout_uri`（仅 `clientSettings` 中的 `unipass.backchannel_logout_uri`）。名称（name）或 scope 的单独变化**不写**历史。
- **不保存任何密钥或签名**：历史只含回调地址、操作类型、操作人、原因与时间戳。`register` 在同一事务内先落注册行与审计，再写 `REGISTER` 快照；`update` 在回调变化时同事务写 `UPDATE` 快照。
- 软删除后：注册行保留（`V17` 墓碑），但管理 API 对 `deleted_at` 非空的客户端返回 `404`，历史不可经管理面读取（审计归档仍可保留对应 `auth_audit` 行）。

## 2. 表结构

新增 `V18__client_callback_history.sql`（**不修改 V14–V17**）：

```sql
CREATE TABLE oauth_client_callback_history (
 id uuid PRIMARY KEY,
 seq bigserial NOT NULL,
 client_id varchar(100) NOT NULL REFERENCES oauth2_registered_client(client_id) ON DELETE CASCADE,
 action varchar(16) NOT NULL CHECK (action IN ('REGISTER','UPDATE')),
 redirect_uris jsonb NOT NULL,
 post_logout_redirect_uris jsonb NOT NULL,
 backchannel_logout_uri varchar(1000),
 actor_id uuid NOT NULL REFERENCES iam_user(id),
 reason varchar(500) NOT NULL,
 created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX client_callback_history_time ON oauth_client_callback_history(client_id, created_at DESC);
```

- `redirect_uris` / `post_logout_redirect_uris` 以 `jsonb` 存储精确地址集合；空集合存 `[]`，不为 `NULL`。
- `backchannel_logout_uri` 为空时存 `NULL`（映射自 `clientSettings` 中的 `unipass.backchannel_logout_uri`，空串归一为 `NULL`）。
- 查询以 `ORDER BY created_at DESC, seq DESC LIMIT ?` 返回，最新在前；`seq` 是单调递增的 `bigserial`，用于固定时钟/同一微秒内插入时仍保持追加顺序；`limit` 越界（`<1` 或 `>100`）返回 `400`。

## 3. 接口

- `GET /api/admin/console/clients/{clientId}/history?limit=20`，要求应用管理员角色（`ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_APP`）+ 近期密码与 MFA（复用 `requireAppAdmin`）。返回 `200` 与数组，元素含 `action`、`redirectUris`、`postLogoutRedirectUris`、`backchannelLogoutUri`、`reason`、`createdAt`。
- 客户端不存在或已软删除返回 `404`；`limit` 越界返回 `400`；非应用管理员（含 `ROLE_ADMIN_AUDIT` 与普通用户）返回 `403`。
- 服务层 `ClientAdminService.history(clientId, limit)`：越界先 `400`；客户端缺失或 `isDeleted` 则 `404`；否则 `LIMIT ?` 查询并反序列化 `jsonb`。

## 4. 写入时机（与既有合同一致）

- `register`：保存后**同一事务**内写 `REGISTER`。
- `update`：`callbacksChanged(existing, spec)` 为 `true` 时才写 `UPDATE`；该方法只比较三类回调，不比较 name/scope。
- `rotate` / `setEnabled` / `delete` 不写回调历史（密钥轮换与状态变更由既有审计覆盖）。

## 5. 回滚限制

- 丢弃 `V18` 会丢失全部回调历史表结构与数据；历史查询会因表不存在而失败。该迁移属**单向**，回滚需线下重建表或确认不再需要回调留痕。
- 历史本质是审计衍生数据，不影响注册行、状态或密钥；因此回滚 `V18` 不影响应用运行，仅丢失回溯能力。

## 6. 未做（保留在 docs/32 N2）

- **多代前序密钥**（当前仅保留一代前序，长周期轮换回退窗口受限）。
- **按客户端的自定义轮换窗口**（目前为全局 `unipass.clients.secret-rotation-window`，1 分钟–7 天）。
- 历史**不记录** name/scope 变化、密钥轮换、状态变更；如需全量配置时间线，属后续扩展。
- 物理删除、`oidc_logout_task` 围栏等产品决策见 docs/32 N2。

## 7. 覆盖与未覆盖边界

- 服务层 `ClientAdminIT`：`register→1 条 REGISTER`；改回调 → `2 条且最新为 UPDATE`；只改名 → 仍 `2 条`；`limit 0/101→400`；`delete` 后 `history→404`；未知 `client→404`；快照含新回调且无密钥。
- HTTP `ClientManagementHttpIT`：`ADMIN_APP`/`SYSTEM_ADMIN` 读 `200` 且含 `REGISTER`、无 `secret`；`ROLE_ADMIN_AUDIT` 与普通用户 `403`；`delete` 后 `404`；`seed()` 的 `TRUNCATE` 列表已含 `oauth_client_callback_history`，避免跨用例残留。
- 门户 `clients.test.ts`：点击「回调历史」后 `GET` 并渲染 `action`/回调；无密钥/存储泄漏；不破坏既有用例。
- **未覆盖**：历史跨多页（仅 `limit` 单一窗口）；多实例并发写入历史行的极端竞争（与注册行同事务，未单独起负向 IT）；管理端审计查询对回调历史行的专项断言（仅复用既有审计能力）。
