# 密码重置验证与管理员恢复

2026-10-18。本次接入 T3 的邮箱链接、自助重置、管理员重置和证据恢复 HTTP。真实邮件服务、真实目录历史策略、门户重置页面以及故障演练尚未验收。短信与飞书验证仍待后续适配；当前不把它们伪装成邮箱验证。

## 可信联系资料

匿名请求只接受员工号，不接受自行填写的邮箱、手机号、目标用户 UUID 或验证通过声明。收件人只能来自 `recovery_contact` 中已核验的资料；这些资料不根据邮箱自动合并身份。

操作员从已核验 HR/目录名单中确认不可变用户 UUID、邮箱归属与证据引用，准备受保护 JSON 文件：

```json
{"userId":"实际身份UUID","email":"已核验地址","evidenceRef":"ticket:verified-roster-2026"}
```

在已经升级 V5 的数据库上执行：

```powershell
java '-Dloader.main=com.unipass.server.RecoveryAdminCli' -cp iam-server/target/iam-server-0.1.0-SNAPSHOT-exec.jar org.springframework.boot.loader.launch.PropertiesLauncher provision-contact protected-contact.json
```

CLI 只需要数据库配置，不启动 HTTP、Redis、目录或邮件连接。导入代表操作员对联系资料归属的外部核验，不是 CLI 已通过邮件验证；证据文件应按企业取证流程保管。输入地址拒绝 CR/LF、地址列表和显示名称，输出不回显邮箱。新增或变更联系资料会生成新 contact_version、提高 auth_epoch 并使旧邮件 proof 失效；BLOCKED/禁用账号不允许用此命令修改联系资料。

## 请求、异步投递与验证

1. 浏览器先取 `GET /api/public/csrf`，所有后续 POST 都带对应 CSRF header。已知、未知、无联系资料和被限速员工号均返回相同 202 accepted；不返回是否存在账号、邮箱或投递状态。
2. Redis 对每个员工号与直连 IP 的摘要计数，分别每 15 分钟最多 5 次、20 次；受限仍返回相同 accepted，但不新增发送任务。Redis 故障统一 503。当前未做统计上的响应时间均衡，不能声称已消除全部时序枚举风险。
3. 合格账号只持久化无秘密的 `reset_mail_request`。任务领取用 PG SKIP LOCKED 与 lease_token，30 秒租约；SMTP 调用期间不持 PG 锁。每次尝试先生成随机 256 位 proof，只存 SHA-256 摘要，关联身份 epoch、contact_version 及 10 分钟期限。
4. 原始 proof 只在工作线程与邮件正文中存在，邮件 URL 使用 `/reset#token=...` fragment，避免令牌进入 URL query 与服务端访问日志；GET 不消费 proof，邮件扫描器访问链接不会完成验证。门户页面属于 T7，目前尚未实现。
5. SMTP 结果不明按可重试投递处理，指数退避加抖动，最多 5 次尝试；每次重试生成新 proof 并作废同一请求此前 proof。SENT 只表示 SMTP 发送调用成功，不是收件箱送达证明；最终失败 DEAD、联系资料或账号变化 BLOCKED。过期工作者无法用旧租约覆盖较新结果。
6. 浏览器 POST 验证邮件 proof，PG 锁定身份与 proof，校验状态/epoch/联系版本/期限，消费 proof 并创建可信 EMAIL_LINK 验证记录。随后核心换发 10 分钟一次性 reset_token，仅存摘要；附加摘要绑定到验证浏览器的会话 ID。验证阶段中断可能导致 proof 已消费而未交付 grant，此时请求新邮件，不重用旧 proof。
7. reset-confirm 不能跨浏览器使用 grant。沿用密码核心的 PREPARED/BLOCKED/epoch → 目录写入 → COMMITTED/outbox 状态机；UNKNOWN 仍返回 202，不自动补写密码。重复相同 token/key 返回原操作，不重复写目录。本人状态能力与会话绑定保留 1 小时，授权新密码写入的 grant 仍只有效 10 分钟。

匿名恢复路由不依赖既有登录主体，使用 CSRF 和独立的浏览器能力；因此密码重置导致原登录 epoch 失效后仍可读取自己的恢复操作。其他浏览器和操作 ID 无权读取。邮箱重置不会删除或绕过已有 TOTP 因素。

## 邮件配置与后台任务

`UNIPASS_RECOVERY_EMAIL_ENABLED` 默认为 false；未配置邮件时请求接口统一返回 503。启用后需要：

| 环境变量 | 含义 |
|---|---|
| `UNIPASS_SMTP_HOST` / `UNIPASS_SMTP_PORT` | SMTP 服务器，默认端口 587 |
| `UNIPASS_SMTP_USER` / `UNIPASS_SMTP_PASSWORD` | 非匿名认证账号与密码 |
| `UNIPASS_SMTP_FROM` | 单个经过授权的发件地址 |
| `UNIPASS_ISSUER` | 固定 HTTPS 外部地址，用于邮件链接，不能从请求 Host 头构造 |

采用 Boot BOM 管理的 Jakarta/Angus Mail；强制 STARTTLS、证书主机名与默认信任链验证，不支持降级明文。连接 3 秒、读写各 5 秒超时；这些是网络操作超时，不声称严格覆盖 DNS 与整个 SMTP 会话的统一时限。租约过期与发送结果不明均按上述状态处理。关闭邮件协议调试，默认将邮件库日志级别设为 WARN，不输出邮件正文、OTP、原始 token 或凭证。官方配置依据见 [Angus SMTP 属性](https://eclipse-ee4j.github.io/angus-mail/docs/api/org.eclipse.angus.mail/org/eclipse/angus/mail/smtp/package-summary.html)。

`unipass.jobs.enabled` 默认 true，后台每 5 秒执行邮件领取及过期密码意图扫描；可用 `unipass.jobs.recovery-delay-ms` 调整。测试明确禁用调度并手动驱动工作者。过期 PREPARED 仅转 UNKNOWN，不推断目录结果，也不重放密码。尚未实现恢复邮件任务的人工重放界面及历史清理策略。

## 管理员操作

管理接口要求浏览器会话、CSRF、当前 PG 角色及最近 MFA；写操作还由密码核心检查最近 5 分钟密码认证、当前 epoch/gate。权限分别为 `ROLE_ADMIN_PASSWORD_RESET` 和 `ROLE_ADMIN_PASSWORD_RECOVERY`，不把普通用户或笼统角色视为自动获权。角色管理入口属于 T8，本次不自动创建超级管理员。

管理员必须提供 reason；证据恢复另提供 evidence_ref、明确 committed 决策，且操作处于 UNKNOWN、租约已过期。请求体不接受 actor、auth_epoch、权限或 MFA 时间。写目录或恢复 gate 前先持久化管理员动作意图、原因与幂等上下文，核心操作另有事务审计。相同幂等键改变原因、证据或恢复目标会拒绝。

管理员重置成功后强制目标下一次改密。人工恢复只接受外部证据已核验的明确决策；API 只约束证据引用格式与权限，不验证工单实际内容，不能用该接口替代人工取证。重复相同管理员、相同决策和证据返回原状态，矛盾决策拒绝。管理员与目标身份按 UUID 顺序加锁，避免相反目标的交叉锁顺序。

| 方法与路径 | 内容 |
|---|---|
| `POST /api/password/reset/request` | employee_no；统一 accepted |
| `POST /api/password/reset/verify` | token（邮件 proof）；返回 reset_token、expires_at |
| `POST /api/password/reset/confirm` | reset_token、new_password、confirm_password、Idempotency-Key |
| `GET /api/password/reset/operations/{id}` | 当前验证浏览器拥有的恢复操作 |
| `POST /api/admin/password/users/{id}/reset` | new_password、confirm_password、reason、Idempotency-Key |
| `POST /api/admin/password/operations/{id}/recover` | confirmed_committed、reason、evidence_ref、Idempotency-Key |
| `GET /api/admin/password/operations/{id}` | 当前管理权限与近期 MFA 下读取状态 |

## 验证与上线限制

测试在真实 PG/Redis 上验证 proof/浏览器绑定、并发一次消费、过期与联系版本撤销、不同浏览器隔离、发送重试换 proof、过期租约与 DEAD、请求限速、旧 JWT 吊销、管理权限实时读取、MFA、证据及幂等恢复。打包 CLI 已纳入集成测试；SMTP 测试连接真实本机 TCP 对端，验证服务不提供 STARTTLS 时不发送 AUTH、邮件或恢复 proof。

正常邮件送达采用测试适配器，未连接企业 SMTP、未实测邮件送达率或真实认证器/目录。V5 为增量迁移；旧版服务无法正确处理新增能力，不可删除表后当作无损回退。恢复联系资料、验证摘要、任务和审计包含个人或安全元数据，生产保留、访问和备份政策需在 T8/T11 落实。P2 及后续阶段保持未整体验收。
