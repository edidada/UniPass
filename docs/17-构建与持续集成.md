# JDK 17 构建与持续集成

2026-10-19。Maven 多模块为主构建，根 POM 固定 `java.version=17`、`maven.compiler.release=17`，保留编译参数名供 Spring 绑定。服务与测试都使用 JDK 17。Gradle 方案放在独立分支 `build/gradle-jdk17`，不替换 Maven 主线。

## Maven

```powershell
pwsh -NoProfile -File scripts/verify-all.ps1 -RedisExecutable 'redis-server 完整路径'
```

等价跨平台命令为 `mvn -B -ntp clean verify -Pintegration -Dtest.redis.executable=/path/to/redis-server`。`mvn test` 只运行单元测试，不得作为完整集成验证。测试自行创建真实 PostgreSQL 和带随机密码的独立 Redis 进程，无需 Docker；嵌入式 PG 不能以 Linux root 运行。

`iam-identity` 操作员可执行包为 `*-cli.jar`，`iam-server` 可执行包为 `*-exec.jar`，普通 JAR 仍可作为模块依赖。生成的证书、测试数据库、报告和临时文件均在忽略的 target 下，生产凭证不得写入仓库。

## GitHub Actions

[工作流](../.github/workflows/maven.yml) 在 push、pull_request 和手工触发时，使用 Ubuntu 24.04、Temurin 17，安装测试 Redis，执行 `clean verify -Pintegration`。Actions 固定到已核对版本的提交 SHA；权限只读，不配置部署、发布或企业秘密。报告只归档 Surefire/Failsafe XML/TXT，不上传测试私钥或数据库目录。

当前本地仓库未设置 remote。`gh run list --limit 3` 已执行，返回 `failed to determine base repo: no git remotes found`，因此远程 Actions 状态为 **未运行/未验证**。本地测试通过不能替代远程成功记录。确定目标仓库并推送后，应执行：

```powershell
gh run list --workflow maven.yml --limit 5
gh run view <run-id> --exit-status
gh run view <run-id> --log-failed
```

检查 run 对应的 head SHA 与待交付提交一致，失败修复后重新检查最终成功的 run。未取得该记录前，保留远程 CI 待验状态。

## Gradle 分支

分支须保持相同四个模块、JDK 17、依赖基线、可执行 CLI/服务与真实 PG/Redis 集成用例。Gradle 不能只代调 Maven 或跳过打包后的 CLI 测试。具体命令与本地验证记录在该分支补充；当前以已实际执行的验证为准。
