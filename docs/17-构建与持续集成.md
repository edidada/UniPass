# JDK 17 构建与持续集成

2026-10-19。Maven 多模块为主构建，根 POM 固定 `java.version=17`、`maven.compiler.release=17`，保留编译参数名供 Spring 绑定。服务与测试都使用 JDK 17。Gradle 方案放在独立分支 `build/gradle-jdk17`，不替换 Maven 主线。

## Maven

```powershell
pwsh -NoProfile -File scripts/verify-all.ps1 -RedisExecutable 'redis-server 完整路径'
```

等价跨平台命令为 `mvn -B -ntp clean verify -Pintegration -Dtest.redis.executable=/path/to/redis-server`。`mvn test` 只运行单元测试，不得作为完整集成验证。测试自行创建真实 PostgreSQL 和带随机密码的独立 Redis 进程，无需 Docker；嵌入式 PG 不能以 Linux root 运行。

`iam-identity` 操作员可执行包为 `*-cli.jar`，`iam-server` 可执行包为 `*-exec.jar`，普通 JAR 仍可作为模块依赖。生成的证书、测试数据库、报告和临时文件均在忽略的 target 下，生产凭证不得写入仓库。

## Gradle 分支

`build/gradle-jdk17` 分支保留相同五个模块，使用 Gradle Wrapper **8.14.3**，toolchain/release 均为 **17**，不代调 Maven。Wrapper 固定官方分发包 SHA-256，首次执行需要下载网络。默认从 Maven Central 获取依赖；`-PlocalMavenRepository=<本地 Maven 仓库>` 可复用已有缓存，不把本机路径写入构建配置。

```powershell
pwsh -NoProfile -File scripts/verify-gradle.ps1 -RedisExecutable 'redis-server 完整路径'
# 或直接执行；Linux/macOS 使用 ./gradlew
.\gradlew.bat --no-daemon clean build '-PtestRedisExecutable=redis-server 完整路径'
```

`build` 同时执行单元测试与 `integrationTest`；单独 `test` 不含 `*IT`。所有集成测试仍使用真实 PG/Redis，并验证打包后的 CLI。输出在各模块 `build/libs`；操作员包为 `*-cli.jar`，服务为 `*-exec.jar`，普通模块 JAR 保留。Gradle CLI 使用 Boot 嵌套库加载器，Maven CLI 使用 shade；操作员命令一致，布局和包摘要不同，不能混用产物摘要。

依赖管理显式保留领域库 JDBC 42.7.8 与服务 Boot BOM 的运行时覆盖，JUnit 统一 5.13.4，服务 Commons IO 对齐 Maven 产物的 2.21.0，避免 Gradle 的冲突选高和 Boot 自动 BOM 改变领域库基线。业务依赖与产物启动均由同一套用例覆盖。

分支包含独立 [Gradle 工作流](../.github/workflows/gradle.yml)，在 JDK 17 下执行 `./gradlew --no-daemon clean build`，仅上传测试 XML。Maven 工作流同时保留。当前无 Git remote，两个工作流都没有远程成功证据；本地结果不能代替 GitHub Actions 状态。主线功能变更合并到 Gradle 分支后，应重新执行两种构建，不能拿旧分支的成功验证新主线。

官方参考：[GitHub Maven CI](https://docs.github.com/en/actions/tutorials/build-and-test-code/java-with-maven)、[setup-java](https://github.com/actions/setup-java)、[Gradle Java 测试](https://docs.gradle.org/8.14.3/userguide/java_testing.html)。

## iam-portal 前端模块与 CI（2026-10-23，远程未验证）

第六个 Maven 模块 `iam-portal` 为 Vue3/TypeScript 门户：frontend-maven-plugin 2.0.2 固定 Node v24.22.1/npm 11.19.1（安装目录 `iam-portal/target/tooling`），`.npmrc` 官方 registry 加 `noproxy=registry.npmjs.org` 规避继承代理/镜像卡死。模块生命周期在 generate-resources 阶段执行 `npm ci --no-audit --no-fund` 与 `npm run verify`（vue-tsc --noEmit → vitest run → vite build），产物进 `iam-portal/target/classes/META-INF/resources/portal`，JUnit 报告为 `iam-portal/target/frontend-test-results.xml`。`iam-server` 只声明普通 `com.unipass:iam-portal` 模块依赖，资源由类路径 `META-INF/resources` 提供，无编译产物互拷。本地禁止运行该工具链（“不新增本地构建入口”）；此前 `portal-verify.log` 的 10 项前端结果属于禁止前的一次性本地证据，不代表之后源码。

[maven 工作流](../.github/workflows/maven.yml) 无独立前端入口：整个 reactor 先后完成前端与 Java 的所有单元/集成与独立 RP 测试；归档路径新增 `**/target/frontend-test-results.xml`，并新增打包校验步骤（exec jar 必须包含 `BOOT-INF/lib/iam-portal-*.jar`，portal jar 必须包含 `META-INF/resources/portal/index.html` 与 assets）。`OidcFlowIT` 同时以 HTTP 实际拉取一个构建出的 `/portal/assets/**` 资源，验证打包资源可被运行时解析。远程 Actions 仍因无 remote 而未运行；此前 177 项双构建证据不含本模块，不得沿用。

Gradle 分支 `build/gradle-jdk17` 同步等价：settings 增加 `iam-portal`，node-gradle 7.1.0（apply false）提供 `nodeSetup/npmSetup/npmCi/portalTypecheck/portalTest/portalBuild`，Node/npm 版本与之相同；构建产物进 `build/portal-dist` 并经 `sourceSets.main.resources` 进 portal jar，`iam-server` 以 `implementation project(':iam-portal')` 打包；前端 vitest JUnit 经 `UNIPASS_PORTAL_REPORT` 重定向进模块 `build/frontend-test-results.xml`（随 `gradle clean` 清除，无陈旧报告），归档路径为 `**/build/frontend-test-results.xml`。gradle 工作流同样归档前端 JUnit 并校验 exec jar 相依与 portal jar 资源。`integrationTest` 选择规则（`**/*IT.class`）与属性传递不变。分支内 `.npmrc`/`.gitignore` 随 portal 源文件复制，分支自身构建文件（build.gradle/settings.gradle）由本分支维护，不从 Maven 拷贝替换。
