# 归档 worker 多实例选举

> 本增量用 PostgreSQL 会话级 advisory lock 保证同一时刻只有一个实例执行定时审计归档；拿不到锁的实例跳过本轮，不再重复搬运/重复批次。状态为**编码增量**，仅由远程 CI 验证。

## 1. 语义

- `ArchiveElection.tryRun(task)` 在一个池化连接上执行 `pg_try_advisory_lock(<固定 key>)`：
  - 拿到锁：执行 task（归档批次循环），在 `finally` 中用**同一连接** `pg_advisory_unlock`。
  - 拿不到：立即返回 false，本轮不归档、不写批次。
- 锁是**会话级**的：实例崩溃/连接关闭时 PostgreSQL 自动释放；不会留下永久死锁。
- `AuditArchiveWorker.run()` 把原批次循环放进 `tryRun`；拿不到锁时不记录失败、不改动数据。
- 归档事务仍是短事务（`AuditMaintenanceService.archiveDue` 内部），advisory lock 只负责跨实例互斥，不扩大事务持有时间。

## 2. 边界

- 只保证**同一 PostgreSQL 数据库**内的实例互斥；跨库/跨区域冷存储仍不在本轮。
- 锁 key 固定，多个不同作业若复用同一 key 会互相排斥；当前只有归档使用该 key。
- 若进程在持锁期间被 kill -9，连接断开即释放；正在执行的归档事务按其自身事务语义回滚/提交。
- 未实现租约续期/可观测的 `owner` 字段；需要排障时可查 `pg_locks`。

## 3. 测试

`ArchiveElectionIT.onlyOneRunnerHoldsTheElectionAndItReleases`（真实嵌入式 PostgreSQL + Hikari）：
- 线程 A 进入 task 并阻塞在 latch；线程 B 的 `tryRun` 返回 false 且 task 未执行；
- 释放 A 后锁可再次获取，第三个 task 执行成功。
- 既有 `AuditArchiveIT` 的归档/摘要/恢复语义不变。
