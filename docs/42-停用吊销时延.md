# 停用吊销时延（内部 HTTP 证据）

> 本增量把"停用后访问令牌立即失效"变成可核验的端到端 HTTP 断言：停用后同一访问令牌访问 `/oauth/userinfo` 必须在 **5 秒内**返回 401。状态为**编码增量**，仅由远程 CI 验证；不代表真实多实例/LB/浏览器环境。

## 1. 测试路径

- `ClientManagementHttpIT.disableRevokesAccessTokenAtResourceEndpointWithinFiveSeconds`：
  1. SYSTEM_ADMIN 登记机密客户端，走标准授权码 + PKCE 换取 access token；
  2. 先用该 token 访问 `/oauth/userinfo`，断言 200（前置可用性）；
  3. 通过管理 API 停用客户端（204）；
  4. 立即再次访问 `/oauth/userinfo`，断言 401，且从停用请求开始计时 < 5000ms。
- 断言不依赖缓存或消息队列：资源端 JWT 解码时实时查询 `oauth2_authorization.revoked`；停用事务按注册记录 UUID 撤销授权族。
- 入口过滤器 `ClientStatusFilter` 继续阻断 `/oauth/authorize`、`/oauth/token`、`/oauth/introspect`、`/oauth/revoke`；`/oauth/userinfo` 走资源端校验，正好覆盖"已签发令牌"的吊销。

## 2. 能证明与不能证明

**能证明（单实例、本机嵌入式 PG+HTTP）**
- 停用事务提交后，资源端不再接受旧 access token；时延在本测试环境下 < 5s。
- 撤销维度是注册记录 UUID，而非 `clientId` 字符串（上一轮安全修复）。

**不能证明**
- 多实例/多副本、真实 LB、跨主机网络、Redis/数据库复制延迟下的 5 秒目标。
- 浏览器/RP 本地会话清理、跨设备传播、真实用户端到端体验。
- 真实 HTTPS、跨域、移动端。
