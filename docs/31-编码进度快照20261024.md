### 根因（实测定位）

列表行渲染的是 summary 类型，而 `scopes` 只存在于 detail 类型：

- `iam-portal/src/pages/AppsPage.vue:144`（模板单行）：`<p class="muted">{{ client.scopes?.length ? client.scopes.join('、') : '' }}</p>`，`clients` 来源 `AdminClientListPage.entries`。
- `iam-portal/src/api.ts:11`：`export interface AdminClientSummary { id; clientId; name; kind; owner; enabled; confidential; issuedAt }` —— 无 `scopes`；`:12` `AdminClientDetail extends AdminClientSummary { ... scopes: string[] ... }`。
- `iam-server/.../ClientManagementService.java:73`：`record ClientSummary(String id, String clientId, String name, String kind, String owner, boolean enabled, boolean confidential, Instant issuedAt)` —— 服务端摘要同样无 scopes；`:75` `ClientDetail` 才有 `List<String> scopes`。
- 同文件 `list()` 的 SQL：`SELECT id,client_id,client_name,enabled,client_id_issued_at,client_authentication_methods,client_settings FROM oauth2_registered_client ...`，未取 scope 列；但 `client_settings` 已在选择列中，Spring 授权服务器把 scopes 存在该 JSON 内（detail 路径即如此读取）。

两个候选修法（本文档只记录，**未改动任何应用代码**，等确认后再动）：

1. 后端 `ClientSummary` 增加 `scopes`（从已选出的 `client_settings` 解析，无需额外 join），前端 `AdminClientSummary` 同步加字段——列表页保持现有展示。
2. 前端列表行不再渲染 `scopes`，scopes 仅在详情面板显示——服务端契约与"列表不含敏感字段"的既有说明都不变。

注意 CI 与本地走的是同一条门禁（工作流注释明确"整个 reactor 先后完成前端与 Java 的所有单元/集成与独立 RP 测试"），所以当前 HEAD 若直接推送，`Maven JDK 17` 必然在同一处红灯。本轮未推送正是基于这一点。
