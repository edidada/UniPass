# 第一阶段运行与验证

## 1. 构建与测试

需要 JDK 17+、Maven 3.9+，以及首次依赖下载网络。当前本机 JDK 17 构建验证；生产 JDK 21 和其他操作系统尚未执行验证。

```powershell
mvn test -B -ntp
pwsh -NoProfile -File scripts/verify-stage1.ps1
```

第一条仅运行单元/LDAPS 测试；第二条执行完整 `verify -Pintegration`，包含 PostgreSQL 17.6 的迁移及事务测试，并生成可执行 JAR。测试 PG 仅监听 127.0.0.1、随机端口，二进制和数据库临时目录位于模块 `target/embedded-pg`，结束时关闭测试进程。该测试库不用于生产。

如需使用外部**专用空测试库**：

```powershell
mvn verify -Pintegration '-Dtest.db.url=jdbc:postgresql://127.0.0.1:5432/unipass_test' '-Dtest.db.user=unipass_test' '-Dtest.db.password=<仅测试口令>'
```

集成测试会清空该测试库内项目表的测试数据，不要连接已有业务数据的数据库。实际自动化应由安全变量注入测试凭证，避免口令进入 shell 历史。

## 2. 操作员 CLI

CLI 供受控本地操作员使用，操作系统账号、数据库账号与终端审计承担入口控制。HTTP 管理接口及角色鉴权在 T2/T8 实现。环境变量不写入仓库。

| 环境变量 | 含义 |
|---|---|
| UNIPASS_DB_URL / USER / PASSWORD | PG JDBC 地址与账号口令；部署环境应使用独立迁移账号和受限运行账号 |
| UNIPASS_DIRECTORY_TYPE | OPENLDAP 或 AD |
| UNIPASS_LDAP_URL | `ldaps://host:636`，仅一个经过确认的目录节点，无 URL 用户信息或路径 |
| UNIPASS_LDAP_BASE_DN | 查询基础 DN |
| UNIPASS_LDAP_READ_DN / READ_PASSWORD | 最小查询权限，不允许匿名绑定 |
| UNIPASS_LDAP_WRITE_DN / WRITE_PASSWORD | 禁用账号的独立写账号；未设置时不能执行目录写入 |
| UNIPASS_LDAP_WRITABLE_CONFIRMED | 只有显式 true 才允许写操作；不自动切换只读副本 |

导入前，将目录 CA 导入专用 JVM truststore，并用 `-Djavax.net.ssl.trustStore=<path>` 等 JVM 参数配置，严禁在生产注入信任所有证书的 SocketFactory。密码传递给 Java/LDAP 库时可能存在短生命周期字符串，不宣称 JVM 内口令始终可可靠擦除；不缓存、记录或持久化业务密码。

```powershell
$taskJar = 'iam-identity/target/iam-identity-0.1.0-SNAPSHOT.jar'
java -jar $taskJar migrate
java -jar $taskJar preview hr - batch-001 examples/hr-import.csv
java -jar $taskJar report <batch-id>
java -jar $taskJar apply <batch-id> --confirm
java -jar $taskJar disable <iam-user-uuid> --confirm
java -jar $taskJar reconcile
```

`migrate` 和 `report` 仅需数据库配置。`preview` 的 `-` 表示初始空游标；其余批次必须提供上一成功游标。示例 CSV 的 directory_id 是占位 UUID，必须替换为真实 `entryUUID` 或标准 UUID 表示的 AD `objectGUID`。employee_no 来自 HR，并与目录 employeeNumber 核对。

预览返回批次 ID、有效行数及每行结果码；staging 保存待应用的完整非凭证身份属性，操作员应查询确认后再 apply。无效行不应用，有效行及源游标同事务提交；所有行均无效时拒绝推进游标。修复隔离行后以新源版本/游标重新预览，不修改历史 staging。重复批次返回原结果，重复 apply 不重复写入。相同批次内容的重复预览不会重新查询目录，目录变化后应创建新批次。

DN 可变，稳定 UUID 与内部 ID 不变。缺失员工号、重复员工号/UUID、目录映射不一致、旧源版本、跨源接管和自动重新激活会被拒绝。当前实现镜像已有目录身份，目录开户与 HR 拉取调度不在该 CLI 内。

## 3. 离职与故障恢复

disable 返回时仅保证 PG 的禁用与任务已持久化，外部目录变更由 reconcile 单次执行。定时任务可每分钟调度该命令；失败保留 PENDING 和脱敏 error_code，60 秒后可重试。持续 PENDING 需由运维处置，不能视为同步成功。

Worker 崩溃后，租约窗口到期即可重新领取；仅对幂等禁用操作重试。用户改密不能套用此规则，T3 必须实现结果未知状态机。跨服务鉴权必须同时检查 ACTIVE、OPEN 和 token 中的 auth_epoch；PG 不可用时拒绝放行。

## 4. 迁移与回退

V1 是初始增量建表，无既有业务字段删除。首次部署先用迁移账号执行 migrate，再用最小运行权限账号操作。后续升级新增 V2 等脚本，不修改已应用 V1 的校验和。

代码回退保留 V1 表及数据，停止导入和 reconcile 后回到兼容版本；不通过恢复旧备份撤回离职禁用或降低 auth_epoch。生产数据恢复须按运维 SOP 保留安全控制状态并单独验证。本阶段不提供自动 DROP 表回退命令。
