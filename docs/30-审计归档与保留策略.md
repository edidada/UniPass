# 审计归档与保留策略

版本 V1.0（2026-10-24）。T8 第四期编码增量，承接 [应用生命周期与只读审计员](29-应用生命周期与只读审计员.md)。

## 范围

- **迁移行而非删除**：V16 新增 `audit_archive` 与 `audit_archive_batch`。`AuditArchiveService.archive(cutoff, maxRows)` 在单事务内把 `auth_audit` 中早于截止时间的至多 N 行移入归档表并写入批次摘要；`maxRows` 限制 1–10000。
- **完整性**：批次摘要为按 `(created_at,id)` 排序后逐行字段（含 `detail::text`）以 `\u001f` 分隔、SHA-256 十六进制 64 位。`verify(batchId)` 重新计算并与登记摘要比较；不一致时恢复返回 409 且不写入任何行。
- **可恢复**：`restore(batchId)` 先校验摘要，再按原 `id` 回插，`ON CONFLICT (id) DO NOTHING` 保证重试幂等；每次恢复尝试都会留审计记录（即使本次恢复 0 行），批次记录保留以便追溯。恢复不会删除归档。
- **权限**：手工归档/恢复要求 `ROLE_SYSTEM_ADMIN` + 近期密码 + 近期 MFA；只读批次列表与校验沿用 `ROLE_SYSTEM_ADMIN`/`ROLE_ADMIN_AUDIT`。归档/恢复操作本身在业务事务内写入 `AUDIT_ARCHIVED`/`AUDIT_RESTORED` 审计（detail 仅 `batch_id`、`rows`、`operator`），审计失败则整体回滚。
- **定时任务**：`AuditArchiveWorker` 默认关闭（`UNIPASS_AUDIT_ARCHIVE_ENABLED`），开启后按 `UNIPASS_AUDIT_RETENTION`（默认 `P180D`，最少 30 天）分批移动，单次最多 20 批、每批 1000 行，避免长事务；失败仅记录告警，下一次调度重试。系统触发的审计记录 `operator=system`。
- **门户**：管理控制台新增归档卡片（截止时间、批量上限、批次列表、校验、恢复），仅 SYSTEM_ADMIN 可归档/恢复，审计员可查看与校验。

## 边界与未完成

- 归档仍是同库表，不是独立冷存储/对象存储；磁盘容量、分区裁剪与跨库归档未实现。
- 调度器为单实例假设：多实例同时开启时会各自尝试归档；行级 `DELETE ... RETURNING` 保证不会重复归档，但批次之间可能出现较小批。生产建议仅在一个实例开启。
- 未实现按分区自动创建/滚动（T8 的"按时间分区"）、外部 WORM/对象锁、加密与密钥托管。
- 恢复不校验行级签名之外的调用方上下文；审计归档的保留期限小于真实合规要求时需外部策略补充。
- 本增量未包含跨版本回退演练；回退到 V15 及更早版本时归档表被忽略，归档中的记录不会自动回到活跃表。

## 测试

`AuditArchiveIT`（真实嵌入式 PostgreSQL）：仅移动早于截止时间的行、批次行数与 64 位摘要、未过期行保留、批次列表、完整性通过；恢复回插全部行、重复恢复返回 0、篡改归档行后校验失败且恢复 409 不写入；空选择不建批次、批量上限截断；非管理员/审计员不能归档、审计员可读批次与校验但不可恢复；未知批次 404、非法截止时间/批量拒绝；系统归档的 `operator=system` 归属与 `AUDIT_ARCHIVED` 记录。

远程 Maven/Gradle 结果见本次提交的 workflow；本机未执行构建。

## 运维

1. 启用前确认库容量与备份策略；`UNIPASS_AUDIT_RETENTION` 不得低于合规期限（默认 180 天）。
2. 手工归档建议在低峰执行并记录批次 ID；恢复前先 `GET .../audit/archive/{id}` 校验。
3. 归档批次与摘要不可修改；如需重新归档已恢复记录，请使用新的截止时间。
4. 多实例部署时只在一个实例设置 `UNIPASS_AUDIT_ARCHIVE_ENABLED=true`。
